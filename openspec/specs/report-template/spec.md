# report-template Specification

## Purpose
Определяет, как логика отчёта описывается отдельно от кода: декларативный шаблон секций, переиспользуемые поставщики фактов, сборка отчёта движком, проверка шаблона, версионирование и выгрузка готового отчёта.

## Requirements

### Requirement: Декларативный шаблон отчёта

Состав отчёта SHALL описываться отдельным файлом шаблона, а не кодом: для каждой секции задаются идентификатор, заголовок, источник фактов, тип вывода, параметры и признак интерпретации.

#### Scenario: Отчёт по шаблону

- **WHEN** агент формирует разбор портфеля
- **THEN** набор и порядок секций берутся из шаблона

#### Scenario: Шаблон без обязательных полей

- **WHEN** в секции шаблона отсутствует идентификатор или источник фактов
- **THEN** старт завершается ошибкой конфигурации с указанием секции

### Requirement: Изменение отчёта без правки кода

Сервис SHALL позволять добавлять, убирать и переупорядочивать секции, менять их заголовки и параметры правкой шаблона без изменения кода.

#### Scenario: Добавлена секция

- **WHEN** в шаблон добавлена секция с существующим поставщиком фактов
- **THEN** она появляется в отчёте после перезапуска без правок кода

#### Scenario: Секция убрана

- **WHEN** секция удалена из шаблона
- **THEN** она исчезает из отчёта, а данные для неё перестают запрашиваться

### Requirement: Пороги и периоды в шаблоне

Пороги концентрации, целевые доли, минимальные доли классов и набор периодов SHALL задаваться в шаблоне и MUST NOT быть зашиты в код отчёта.

#### Scenario: Изменён порог концентрации

- **WHEN** порог высокой концентрации изменён в шаблоне
- **THEN** оценка концентрации в отчёте меняется без правок кода

#### Scenario: Изменён набор периодов

- **WHEN** в шаблоне заданы периоды «день, месяц, год»
- **THEN** отчёт показывает динамику именно за эти периоды

### Requirement: Реестр поставщиков фактов

Сервис SHALL предоставлять реестр поставщиков фактов, каждый из которых возвращает факты секции или явное «нет данных», и SHALL переиспользовать поставщиков между шаблонами.

#### Scenario: Два шаблона используют один источник

- **WHEN** два шаблона ссылаются на одного поставщика структуры портфеля
- **THEN** используется одна и та же реализация поставщика

#### Scenario: Неизвестный поставщик

- **WHEN** шаблон ссылается на поставщика, которого нет в реестре
- **THEN** старт завершается ошибкой конфигурации с именем поставщика

### Requirement: Интерпретация только для отмеченных секций

Модель SHALL вызываться только для секций с признаком интерпретации и MUST NOT пересказывать секции, собранные кодом.

#### Scenario: Секции с интерпретацией

- **WHEN** в шаблоне признак интерпретации стоит у секций «макро» и «итог»
- **THEN** модель формирует только эти две секции

#### Scenario: Интерпретация недоступна

- **WHEN** модель вернула ошибку или пустой ответ
- **THEN** отчёт отдаётся без интерпретационных секций с явной пометкой и признаком частичности

### Requirement: Версионирование шаблона

Шаблон SHALL иметь версию, а готовый отчёт SHALL содержать версию шаблона, по которому он собран.

#### Scenario: Отчёт после правки шаблона

- **WHEN** шаблон обновлён до новой версии
- **THEN** ранее сохранённые отчёты сохраняют свою версию и не пересобираются

### Requirement: Выгрузка готового отчёта

Сервис SHALL сохранять собранный отчёт с идентификатором и SHALL отдавать его на выгрузку в markdown, JSON и HTML.

#### Scenario: Отчёт сохранён

- **WHEN** разбор портфеля завершён
- **THEN** ответ содержит идентификатор отчёта и текст отчёта

#### Scenario: Выгрузка в JSON

- **WHEN** клиент запрашивает отчёт по идентификатору в формате JSON
- **THEN** сервис возвращает структурированные секции с фактами, а не только текст

#### Scenario: Отчёт не найден

- **WHEN** клиент запрашивает несуществующий идентификатор отчёта
- **THEN** сервис отвечает `404` с единым форматом ошибки

### Requirement: Секция с недоступным источником

Если поставщик фактов недоступен, шаблон MUST оставаться исполнимым: секция выводится с сообщением об отсутствии данных и причиной.

#### Scenario: Поставщик новостей недоступен

- **WHEN** поставщик новостей вернул ошибку
- **THEN** секция новостей содержит сообщение о недоступности, а остальные секции собираются как обычно

### Requirement: Несколько шаблонов отчёта

Сервис SHALL поддерживать несколько шаблонов и выбор используемого по умолчанию, чтобы разные отчёты собирались из одного набора поставщиков.

#### Scenario: Шаблон по умолчанию

- **WHEN** в конфигурации не указан иной шаблон
- **THEN** разбор портфеля собирается по шаблону по умолчанию

#### Scenario: Другой шаблон

- **WHEN** в конфигурации указан другой шаблон отчёта
- **THEN** разбор собирается по нему без правок кода
