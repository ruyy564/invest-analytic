# Spec Delta

## Purpose

Позволяет выбирать LLM-провайдера и модели через конфигурацию, чтобы код агента не зависел от конкретной библиотеки и провайдера, а смена модели была правкой `.env`.

## ADDED Requirements

### Requirement: Выбор провайдера из конфигурации
Сервис SHALL создавать модель по значению `LLM_PROVIDER`, поддерживая `gigachat`, `openai` и `openai-compatible`, и MUST завершать старт с ошибкой при неизвестном значении, перечисляя поддерживаемые варианты.

#### Scenario: Провайдер указан верно
- **WHEN** `LLM_PROVIDER=gigachat` и заданы креденшелы GigaChat
- **THEN** сервис стартует и создаёт модель GigaChat для ролей ответа и классификации

#### Scenario: Неизвестный провайдер
- **WHEN** `LLM_PROVIDER` содержит значение, которого нет в реестре
- **THEN** сервис не стартует и сообщает список поддерживаемых провайдеров

### Requirement: Роли моделей
Сервис SHALL использовать отдельные модели для ответа (`LLM_MODEL`) и для классификации (`LLM_ROUTER_MODEL`), подставляя модель ответа при отсутствии второй настройки.

#### Scenario: Модель классификации не задана
- **WHEN** задана только `LLM_MODEL`
- **THEN** классификация и ответ выполняются одной и той же моделью

#### Scenario: Модель классификации задана
- **WHEN** заданы `LLM_MODEL` и `LLM_ROUTER_MODEL`
- **THEN** классификация использует `LLM_ROUTER_MODEL`, а ответ — `LLM_MODEL`

### Requirement: Условная проверка креденшелов
Сервис SHALL требовать креденшелы, специфичные для выбранного провайдера, и MUST NOT требовать креденшелы других провайдеров.

#### Scenario: GigaChat без креденшелов
- **WHEN** `LLM_PROVIDER=gigachat` и `GIGACHAT_CREDENTIALS` пуст
- **THEN** старт завершается ошибкой конфигурации с именем отсутствующей переменной

#### Scenario: OpenAI-совместимый провайдер
- **WHEN** `LLM_PROVIDER=openai-compatible`
- **THEN** обязательны `LLM_API_KEY` и `LLM_BASE_URL`, а переменные `GIGACHAT_*` не проверяются

### Requirement: Независимость кода агента от провайдера
Сервис SHALL передавать модель в узлы графа через общий интерфейс, чтобы смена провайдера выполнялась только конфигурацией.

#### Scenario: Смена провайдера
- **WHEN** `LLM_PROVIDER` меняется с `gigachat` на `openai`
- **THEN** код узлов и графа не меняется, а прогон использует модель нового провайдера

### Requirement: Фолбэк структурированного вывода
Сервис SHALL использовать структурированный вывод для классификации, а при ошибке провайдера MUST переходить к текстовому ответу с разбором метки.

#### Scenario: Провайдер не поддерживает вызов функций
- **WHEN** запрос структурированного вывода завершается ошибкой
- **THEN** классификация повторяется запросом с инструкцией ответить одной меткой, и метка разбирается из текста

### Requirement: Недоступность провайдера
Сервис SHALL возвращать ошибку `llm_unavailable` с ответом `502`, если провайдер недоступен на шаге формирования ответа.

#### Scenario: Ошибка провайдера
- **WHEN** провайдер возвращает сетевую ошибку или таймаут
- **THEN** сервис отвечает `502` с кодом `llm_unavailable` и не отдаёт незавершённый ответ
