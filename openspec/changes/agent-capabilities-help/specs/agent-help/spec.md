# Spec Delta

## Purpose

Отвечает на вопросы о том, что умеет агент: перечисляет возможности, приводит
примеры вопросов под каждую из них и обозначает границы применимости, чтобы
пользователь сразу понимал, чем сервис может помочь.

## ADDED Requirements

### Requirement: Перечень возможностей агента

Справка SHALL перечислять актуальные возможности сервиса и MUST соответствовать
реальному поведению: портфель и счета, разбор портфеля, разбор счёта, разбор
бумаги, новости рынка по периодам, аналитика и дивиденды, макро и налоговый
контекст.

#### Scenario: Справка перечисляет возможности

- **WHEN** пользователь спрашивает «что ты умеешь?»
- **THEN** ответ содержит разделы: портфель и счета, разбор портфеля, разбор счёта, разбор бумаги, новости рынка, аналитика и макро
- **AND** ни одна из перечисленных возможностей не отсутствует в системе

#### Scenario: Устаревшая возможность не показывается

- **WHEN** возможность отключена конфигурацией (например, новостная ветка)
- **THEN** она либо не упоминается в справке, либо помечена как отключённая
- **AND** справка не обещает того, чего сервис не сделает

### Requirement: Примеры вопросов

Для каждой возможности справка SHALL приводить пример вопроса, который
пользователь может задать дословно. В примерах счёт SHALL называться по имени,
а не по номеру.

#### Scenario: Примеры под каждую возможность

- **WHEN** справка сформирована
- **THEN** рядом с каждой возможностью указан хотя бы один пример вопроса
- **AND** примеры соответствуют сценариям, которые сервис действительно обслуживает

#### Scenario: Счёт называется словами

- **WHEN** в справке приводится пример разбора счёта
- **THEN** пример содержит название счёта (например, «разбери счёт Портфельное инвестирование»)
- **AND** номера счетов в примерах не используются

### Requirement: Границы применимости

Справка SHALL явно перечислять, чего сервис не делает: не совершает торговых
операций, не даёт индивидуальных инвестиционных рекомендаций и не отвечает на
вопросы вне инвестиционной области.

#### Scenario: Границы перечислены

- **WHEN** пользователь читает справку
- **THEN** в ней сказано, что торговые операции не выполняются
- **AND** сказано, что ответы носят информационный характер, а не являются индивидуальной инвестиционной рекомендацией

#### Scenario: Посторонняя тема остаётся отказом

- **WHEN** пользователь спрашивает «какая завтра погода в Москве?»
- **THEN** ответ остаётся отказом по теме, а не справкой о возможностях

### Requirement: Одинаковый ответ на любую формулировку

Справка SHALL быть одинаковой для всех формулировок: «что ты умеешь», «чем
можешь помочь», «что здесь можно узнать», «кто ты». Текст MUST NOT зависеть от
случайных решений модели.

#### Scenario: Разные формулировки — один ответ

- **WHEN** пользователь задаёт «что ты умеешь?» и «чем ты можешь помочь?»
- **THEN** оба ответа совпадают по содержанию
- **AND** ни один из них не уходит в отказ по теме

#### Scenario: Справка не классифицируется как посторонняя тема

- **WHEN** вопрос про возможности агента поступает на вход
- **THEN** он определяется как справочный до обращения к модели
- **AND** отказ по теме не формируется

### Requirement: Ответ без данных и без модели

Справка SHALL формироваться без чтения данных брокера, без подтверждения доступа
и без вызова языковой модели.

#### Scenario: Данные не читаются

- **WHEN** пользователь спрашивает «что ты умеешь?»
- **THEN** запросы к брокеру и источникам не выполняются
- **AND** подтверждение не запрашивается

#### Scenario: Ответ не зависит от доступности модели

- **WHEN** провайдер модели недоступен
- **THEN** справка всё равно возвращается
- **AND** её содержание не меняется

### Requirement: Подсказка следующего шага

Справка SHALL заканчиваться предложением конкретных вопросов, с которых можно
начать работу.

#### Scenario: Что спросить дальше

- **WHEN** справка показана пользователю
- **THEN** в конце перечислены 2–3 примера вопросов, например про состав портфеля, разбор портфеля и новости рынка
