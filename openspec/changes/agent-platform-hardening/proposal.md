# Proposal

## Why

Поведение агента сейчас задано кодом в четырёх местах одновременно: регулярки
маршрутизации, фиксированный план сбора, промпты разделов и строковые эвристики
в узлах (`REPORT_MARKERS`, `PORTFOLIO_INTENT`, `REFUSAL`). Из-за этого любая
новая формулировка вопроса требует правки кода, изменение одного правила
непредсказуемо меняет другой сценарий, а качество ответа нельзя измерить —
проверяются только структуры и регулярки, но не поведение агента.

Наблюдаемость тоже частичная: трейсинг в LangSmith есть, но локальные логи —
неструктурный текст, идентификатор прогона добывается опросом внешнего API, и
по факту ответа нельзя восстановить, что решил роутер, какие инструменты
вызывались и почему часть данных отсутствует.

## What Changes

- **Evals как основной инструмент проверки.** Корзина `test/fixtures/dialogues.json`
  превращается в набор кейсов с грейдерами (код и LLM-судья), несколькими
  прогонами на кейс и раннером, который умеет работать офлайн на записанных
  ответах MCP и вживую. Появляются метрики: успех задачи, точность выбора
  инструментов, доля отказов модели, стоимость и задержка.
- **Наблюдаемость прогона.** Структурные JSON-логи (pino) с `runId`, который
  генерирует сам сервис; журнал прогона (решения, вызовы, покрытие, стоимость)
  и воспроизведение по `runId`; метрики по интентам вместо ручного разбора
  текстовых логов.
- **Guardrails как отдельная способность.** Отказ по темам вне области, запрет
  торговых действий, обработка отказа модели, защита от инструкций внутри
  внешних данных (новости, описания эмитентов), маскирование секретов,
  лимиты шагов и стоимости.
- **Переход к агентской топологии.** **BREAKING** Граф сжимается до шести нод
  верхнего уровня (`guard`, `router`, `agent`, `tools`, `approve`, `respond`)
  плюс подграф `review` для детерминированного разбора. Каталог инструментов
  сокращается с ~65 до восьми доменных фасадов, а решения «какие данные нужны»
  и «достаточно ли их» переходят к модели с валидируемым планом и безопасным
  фолбэком.
- **Типизированный контракт узлов.** Вместо опознания отчёта по префиксу строки
  узел возвращает структурированный результат (`facts | analysis | report`),
  а ответ собирается из артефактов.
- **Единый конвейер источников.** `source → extract → normalize → policy →
  dedupe → rank → select → present` с каноническим элементом на zod, политикой
  релевантности в `data/policy/news.yaml` (вместо восьми мест в коде) и отчётом
  стадий, где видно, сколько элементов и по какой причине отброшено.
- **Рефакторинг структуры.** `platform / shared / capabilities / transports`:
  домены как вертикальные срезы (`domain / services / adapters / tools /
  present`), `agent` — только оркестрация, архитектурный тест границ модулей и
  чек-листы добавления ноды, тула, парсера, источника и секции отчёта.
- **Поток событий и отмена.** Прогресс прогона отдаётся клиенту событиями
  (SSE) по мере выполнения, длинный прогон можно отменить, не дожидаясь
  итогового отчёта.
- **Миграция без большого взрыва.** Новое поведение включается флагами
  (`AGENT_MODE`, поэтапные фичафлаги), старые пути остаются re-export'ами,
  тесты зелёные на каждом шаге, переключение — по метрикам evals.

## Capabilities

### New Capabilities

- `agent-evaluation`: набор кейсов, грейдеры и раннер для измерения качества
  агента и регрессий поведения (маршрут, выбор инструментов, содержание ответа).
- `agent-guardrails`: ограничения поведения и безопасность — темы вне области,
  запрет торговых действий, отказ модели, инструкции внутри внешних данных,
  секреты, лимиты шагов и стоимости.
- `agent-streaming`: поток событий прогона и отмена длинного запроса.
- `module-structure`: границы модулей, структура папок, правила расширения
  (нода, тул, парсер, источник, секция отчёта) и архитектурный тест.

### Modified Capabilities

- `agent-observability`: структурированные логи и собственный `runId` вместо
  опроса LangSmith; журнал прогона, воспроизведение и метрики по интентам.
- `data-sources`: конвейер стадий с каноническим элементом и политикой как
  данными; отчёт стадий с причинами отбраковки; golden-тесты парсеров.
- `portfolio-agent`: топология из шести нод и подграфа `review`, каталог из
  восьми инструментов, типизированный контракт результата узла, планировщик с
  безопасным фолбэком.
- `agent-api`: события прогресса и отмена прогона, совместимость существующих
  ответов.
- `approval-policy`: подтверждение чтения данных по умолчанию и отражение
  лимитов прогона в запросе подтверждения.
- `llm-providers`: режим планировщика для выбора инструментов и фолбэк на
  детерминированный план при неполном ответе модели.
- `data-collection`: планы сбора как данные (скиллы) и обязательный сбор
  источников, без которых разбор неполон.

## Impact

- Граф и узлы: `src/agent/graph/*`, `src/agent/nodes/*`, `src/agent/runner/*`,
  `src/agent/subgraphs/*`.
- Транспорты и инструменты: `src/transports/mcp/*` (реестр, прокси, адаптер,
  схемы, бюджет, локальные тулы), `src/tools.module.ts`, `.env.example`
  (`MCP_TINKOFF_ALLOWED_TOOLS`, `AGENT_MODE`, лимиты).
- Источники и знания: `src/capabilities/{news,knowledge,market}/*`,
  `src/shared/parsing/*` (сеть — через `src/platform/http/*`),
  `data/policy/news.yaml`.
- Отчёт: `src/capabilities/reports/*`, шаблон `reports/portfolio-review.yaml`.
- API: `src/transports/http/*` (поток событий, отмена), `docs/api.md`.
- Наблюдаемость: `src/platform/{logging,observability,config,state,llm}/*`,
  зависимость `pino`, `docs/observability.md`.
- Тесты: `test/fixtures/dialogues.json`, `test/unit/*`, `test/e2e/*`, новый
  `test/eval/*`, `test/fixtures/golden/*`, `test/unit/architecture.spec.ts`.
- Документация: `docs/architecture.md`, `docs/structure.md` (новый),
  `docs/evals.md` (новый), `README.md`.
- Обратная совместимость: HTTP-контракт сохраняется; отменяется только старое
  множество интентов/веток графа (BREAKING для внутренней топологии и имён
  инструментов — со алиасами на время миграции).
- Структура `src` после M6: четыре корня (`agent`, `capabilities`, `platform`,
  `shared`, `transports`) и `eval`; старые каталоги (`config`, `state`, `llm`,
  `observability`, `report`, `tools`, `parsing`, `collection`, `accounts`, `api`,
  `mcp`, `news`, `knowledge`, `key-rate`, `commodities`) удалены без
  re-export-двойников.
