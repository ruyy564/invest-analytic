# Design

## Context

Мотивация — в `proposal.md`, требования — в спеках изменения. Существенное для
реализации сейчас:

- разбор уже собирается планом (`buildCollectionPlan`) и рендерится секциями шаблона
  `reports/portfolio-review.yaml` через поставщиков фактов; текст секций пишет модель
  по брифингу (`reports/prompts/interpretation.md`);
- в плане есть прогноз, дивиденды, инсайдеры, свечи, ставка и сырьевой фактор, но нет
  календаря отчётов, фундаментала и дат заседаний ЦБ;
- рыночные факторы числами уже собирает локальный инструмент `market__factors`
  (нефть, курсы, ставка), а драйверы сектора лежат в `data/company-profiles.yaml`;
- проверки поведения уже разделены: юниты, e2e на фейковом MCP, кейсы оценки с
  грейдерами; не хватает корзин как контракта и грейдеров разделов/цитат/чисел.

## Goals / Non-Goals

**Goals:**

- записка по бумаге из блоков: факты → влияющие факторы → хорошо/нейтрально/плохо →
  чего ждём → сценарии → ограничения;
- блоки «влияет» и «чего ждём» наполняются кодом из новых источников плана, а не
  фантазией модели;
- корзины проверок и кодовые грейдеры, по которым видно, что правка ничего не сломала.

**Non-Goals:**

- не делаем торговых рекомендаций и целевых цен сверх данных брокера;
- не добавляем новых внешних провайдеров, кроме read-only инструментов T-Invest MCP;
- не меняем формат API-ответа: записка остаётся текстом ответа и отчёта.

## Decisions

**1. Календарь и фундаментал — новые записи плана, а не отдельный сборщик.**
План уже описывает источники данными (`tool`, `args`, `group`, `priority`) и умеет
бюджет, дедупликацию и покрытие. Добавляем группы `reports_calendar` и `fundamentals`
с приоритетом `optional`: недоступность не должна помечать разбор как неуспешный.
Альтернатива — отдельный «календарный» сборщик — дублирует бюджет и покрытие.

**2. Секции считает код, текст пишет модель.**
Блок «что влияет» и «что хорошо/плохо» собираются поставщиками фактов из уже
собранного (драйверы сектора, рыночные значения, дивиденды, прогноз), а модель
получает их в брифинге как числа и трактует. Альтернатива — просить всё у модели —
возвращает выдуманные числа и непроверяемость.

**3. Календарь ЦБ — файл данных, а не парсинг сайта.**
Даты заседаний меняются 1–2 раза в год и публикуются заранее: `data/cb-meetings.yaml`
(обновляется скриптом). Альтернатива — SOAP-источник ставки не содержит расписания,
а HTML-парсинг календаря хрупок.

**4. Сценарии формулируются через условия, а не через целевые цены.**
Два сценария с условиями («если нефть удержалась выше …») дают инвестору рамку без
обещаний; целевые цены берутся только из консенсуса аналитиков, если он есть.

**5. Корзины — это контракт, а не набор разрозненных тестов.**
Пять корзин (контракты инструментов, маршруты, поведение, аналитика, регрессии)
запускаются своими командами; грейдеры разделов/цитат/чисел кодовые, чтобы результат
не зависел от модели. Кейсы кладутся в каталог и обходятся раннером целиком.
Альтернатива — только LLM-судья: оценки «плывут» и не объясняют провал.

**6. Сбой → кейс с тегом `required`.**
Каждый найденный в эксплуатации дефект (устаревший отчёт, выдуманный тикер, мусор в
новостях) фиксируется дословным вопросом; правка не считается готовой, пока кейс не
проходит. Это уже объявлено в `agent-evaluation`, здесь закрепляется практикой корзин.

## Risks / Trade-offs

- **Рост числа запросов к MCP** (календарь + фундаментал по каждой бумаге) → лимит
  `REVIEW_MAX_INSTRUMENTS`, приоритет `optional`, бюджет прогона и дедупликация плана.
- **Календарь ЦБ устареет** без обновления файла → в записке печатается дата данных
  и предупреждение, если ближайшее заседание в прошлом.
- **Фундаментал брокера неоднороден по бумагам** → блок строится по тому, что есть,
  отсутствие помечается явно, сравнение с медианой считается только при ≥3 бумагах.
- **Грейдеры разделов могут «зашивать» формулировки** → сверяем заголовки разделов,
  а не фразы модели; тексты внутри проверяются только на числа и цитаты.
- **Длиннее ответ** → блоки сжаты по предложению-два, лимит — в шаблоне и промпте.

## Migration Plan

1. Добавить записи плана и группы; существующие разборы работают без новых блоков.
2. Выпустить секции за флагом шаблона (новая версия `portfolio-review.yaml`), при
   откате — прежняя версия шаблона, отчёт остаётся валидным.
3. Корзины вводятся без миграции: старые спеки тестов остаются.

## Open Questions

- Точный формат дат заседаний ЦБ (`YYYY-MM-DD` + тип заседания) уточняется при
  реализации парсера сид-файла.

## Что выяснилось при записи эталонных ответов

Запись транскриптов через живой сервис (GigaChat + реальный MCP) вскрыла четыре
дефекта — они исправлены до архивации:

1. **Инсайдеры и облигации не собирались в разборе**: `perTickerGroups` фильтровал их
   из второй фазы плана, поэтому строки «инсайдеры» и карточка облигации не появлялись.
2. **Причина без ссылки принималась за ответ**: `isGroundedCauseAnswer` довольствовался
   совпадением слов заголовка; пересказ без даты и источника теперь отклоняется, и
   отдаётся `causeFactsAnswer` с цитатами.
3. **GigaChat отклонял историю с параллельными вызовами** (`422: every assistant
   function result must have an assistant function call in history`): новости по
   нескольким бумагам запрашиваются по одной за круг.
4. **Контекст переполнялся полными текстами публикаций**, и провайдер отвечал ошибкой:
   результаты инструментов урезаются до бюджета (`clipToolResults`), а таймаут ответа
   поднят с 15 до 60 секунд — иначе «не удалось за отведённое время» вместо разбора.

Плюс наблюдаемость: ошибка провайдера теперь пишется в лог текстом
(`describeError`), а не `ResponseError: [object Object]`.
