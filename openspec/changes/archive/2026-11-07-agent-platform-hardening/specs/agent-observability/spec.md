# Spec Delta

## MODIFIED Requirements

### Requirement: Структурированные логи
Сервис SHALL писать логи структурированными записями с `runId`, `requestId`, `sessionId`, интентом, источником решения о маршруте, длительностью этапов, именами и результатами вызванных инструментов, покрытием источников и кодами ошибок; текст вопроса MUST NOT попадать в лог без явно включённого флага.

#### Scenario: Логирование вопроса

- **WHEN** флаг логирования текста вопросов выключен
- **THEN** запись лога содержит `runId`, `requestId`, интент, источник решения и длительности, но не содержит текста вопроса

#### Scenario: Машинная обработка логов

- **WHEN** сборщик логов читает поток
- **THEN** каждая запись является валидным JSON-объектом с одинаковыми именами полей

#### Scenario: Решение маршрутизации

- **WHEN** вопрос отнесён к сценарию
- **THEN** запись содержит источник решения (правило, модель или резервный вариант) и итоговый сценарий

## ADDED Requirements

### Requirement: Идентификатор прогона на стороне сервиса

Сервис SHALL генерировать собственный идентификатор прогона до запуска графа, передавать его в метаданные трассировки и MUST NOT зависеть от внешнего API для получения ссылки на трейс.

#### Scenario: Ссылка без опроса внешнего API

- **WHEN** трассировка включена
- **THEN** ссылка на трейс собирается из собственного идентификатора без дополнительных запросов к LangSmith

#### Scenario: Трассировка выключена

- **WHEN** трассировка отключена конфигурацией
- **THEN** идентификатор прогона всё равно создаётся и попадает в логи и журнал

### Requirement: Метаданные прогона в трассировке

Трассировка SHALL содержать версию промптов, сценарий (скилл), набор доступных инструментов, модель и параметры генерации, а также признак частичного результата.

#### Scenario: Сравнение экспериментов

- **WHEN** две версии промпта прогоняются на одном кейсе
- **THEN** в метаданных видны версии промптов, и трейсы можно различить без чтения текста

### Requirement: Журнал прогона

Сервис SHALL сохранять журнал прогона: шаги, вызовы инструментов с аргументами и результатами, причины остановки и покрытие источников, без записи секретов и персональных данных.

#### Scenario: Разбор неудачного ответа

- **WHEN** пользователь сообщает о неверном ответе
- **THEN** по журналу прогона видно, какие шаги выполнялись и какие источники были недоступны

### Requirement: Воспроизведение прогона

Сервис SHALL предоставлять команду воспроизведения прогона по его идентификатору на записанных данных, не обращаясь к внешним источникам.

#### Scenario: Воспроизведение без сети

- **WHEN** выполняется воспроизведение сохранённого прогона
- **THEN** результат воспроизводится на записанных ответах инструментов без сетевых вызовов

### Requirement: Метрики прогонов

Сервис SHALL считать по интентам долю отказов модели, долю частичных результатов, долю ошибок инструментов, стоимость и перцентили задержки.

#### Scenario: Рост частичных результатов

- **WHEN** доля частичных результатов по интенту превышает настроенный порог
- **THEN** метрика доступна для оповещения вместе с разбивкой причин недоступности источников
