# Proposal

## Why

Портфель в Tinkoff Invest — это набор позиций, который нужно периодически пересматривать: что куплено, сколько стоит сейчас, какая доля в общей сумме. Собирать это вручную по приложению брокера и таблицам утомительно, а спрашивать у LLM «на глазок» — значит получать выдуманные числа.

Нужен минимальный работающий каркас сервиса и агент, который отвечает на вопрос «что у меня в портфеле» строго по данным брокера, полученным через MCP. Отдельная цель — заложить два расширяемых шва: смена LLM-провайдера и подключение новых MCP-источников — оба только конфигурацией, без правок кода агента.

## What Changes

- Новый сервис на NestJS + TypeScript (strict): слои `api → agent (LangGraph) → tools (MCP) → observability`, конфигурация через `@nestjs/config` + zod с проверкой на старте.
- Реестр LLM-провайдеров: выбор через `LLM_PROVIDER` (`gigachat`, `openai`, `openai-compatible`), роли «умная модель ответа» и «дешёвая модель классификации», условная валидация креденшелов по провайдеру.
- Реестр MCP-серверов: список серверов из `MCP_SERVERS` с параметрами на каждый сервер, обнаружение инструментов при старте, неймспейсинг имён `<server>__<tool>`, allowlist (по умолчанию ничего не разрешено), таймауты и маппинг ошибок.
- LangGraph-граф `classify → (off_topic → END | agent ⇄ tools → END)` с `ToolNode`, состоянием на `StateSchema`/`MessagesValue` и памятью в рамках процесса по `sessionId`.
- Классификатор области вопроса (`portfolio` / `off_topic`) на дешёвой модели со structured output и текстовым фолбэком, если провайдер не поддерживает вызов функций.
- Ответ по портфелю: позиции (тикер, название, количество, текущая цена, стоимость позиции), итоговая стоимость, валюта, доходность при наличии, время данных и дисклеймер.
- Наблюдаемость: трейс LangSmith на запрос (узлы графа, вызовы MCP, модель и провайдер) и структурные логи с маскированием секретов.
- Подтверждение доступа к данным: перед чтением портфеля агент останавливается в узле `approve` и ждёт явного решения пользователя; без подтверждения данные брокера не запрашиваются, при отказе агент сообщает, что данные не читались. Подтверждение требуется на каждый запрос — ранее данное согласие не переносится. Перечень действий, требующих подтверждения, задаётся отдельным декларативным файлом правил с проверкой на старте, поэтому список меняется без правок графа, роутеров и узлов.
- Персистентное состояние: состояние сессий и ожидающих подтверждений хранится в постоянном хранилище (`SqliteSaver`), переживает перезапуск сервиса, а общие данные (например, счёт по умолчанию) вынесены в глобальное хранилище с пространствами имён по пользователю.
- Явно вне рамок этой итерации: аналитика по отдельной бумаге, фундаментальные показатели, дивиденды, новости, макроэкономика, налоги, ставка ЦБ, аналитика инвест-домов, комментарии Пульса, торговые операции, персистентная история диалогов, UI и стриминг ответа.

## Capabilities

### New Capabilities

- `agent-api`: HTTP-контракт сервиса — приём вопроса, формат ответа и ошибок, health-проверка зависимостей, проверка конфигурации на старте.
- `llm-providers`: выбор и создание модели по конфигурации — поддерживаемые провайдеры, роли моделей, условная валидация креденшелов, поведение при недоступности провайдера.
- `mcp-gateway`: подключение произвольных MCP-серверов из конфигурации — обнаружение инструментов, неймспейсинг, allowlist, таймауты и доменные ошибки.
- `portfolio-agent`: поведение агента — маршрутизация вопроса, отказ по темам вне области, цикл вызова инструментов, лимиты прогона, изоляция сессий, запрет торговых действий.
- `approval-policy`: декларативный файл правил о том, какие действия требуют подтверждения, сопоставление правил с инструментами, поведение по умолчанию и проверка правил при старте.
- `portfolio-report`: содержание ответа о портфеле — состав позиций, итоги, валюта, актуальность данных, пустой портфель и дисклеймер.
- `agent-observability`: трейсинг прогонов в LangSmith и структурное логирование без секретов.
- `state-persistence`: постоянное хранение состояния сессий и ожидающих подтверждений, выбор бэкенда конфигурацией, глобальное хранилище общих данных и очистка устаревших сессий.

### Modified Capabilities

Нет: спецификаций в проекте пока не существует.

## Impact

- **Новый код**: каркас NestJS-приложения, модуль конфигурации, реестр LLM-провайдеров, реестр MCP-серверов с адаптером инструментов, граф LangGraph и промпты, HTTP-контроллер, health, тесты.
- **Новые зависимости**: `@nestjs/config`, `@nestjs/terminus`, `@langchain/langgraph`, `@langchain/langgraph-checkpoint-sqlite`, `@langchain/core`, `@langchain/openai`, `@langchain/mcp-adapters`, `@modelcontextprotocol/sdk`, `langchain-gigachat`, `better-sqlite3`, `langsmith`, `zod`, `dotenv`.
- **Внешние системы**: LLM-провайдер (GigaChat или OpenAI-совместимый), MCP-сервер Tinkoff Invest, LangSmith.
- **Конфигурация**: `LLM_PROVIDER`/`LLM_MODEL`/креденшелы провайдера, `MCP_SERVERS` и `MCP_<NAME>_*`, `TINKOFF_ACCOUNT_ID`, `LANGSMITH_*`; отсутствие обязательных значений блокирует старт.
- **Ограничения**: только read-only доступ к данным, один процесс, состояние сессий в SQLite, нет UI и стриминга.
