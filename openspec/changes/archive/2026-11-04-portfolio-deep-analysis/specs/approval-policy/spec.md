# Spec Delta

## MODIFIED Requirements

### Requirement: Поведение для не перечисленных действий

Для инструментов без правила сервис SHALL применять политику `APPROVAL_UNLISTED` (`require` по умолчанию, `allow` как явное исключение) и SHALL включать такой инструмент в план чтений, если политика требует подтверждения.

#### Scenario: Новый инструмент без правила

- **WHEN** в реестре MCP появился инструмент, которого нет в правилах, и он попал в план сбора
- **THEN** он входит в запрос подтверждения плана и не вызывается до решения пользователя

#### Scenario: Явное разрешение без подтверждения

- **WHEN** в правиле указано `requiresApproval: false`
- **THEN** инструмент вызывается без отдельного подтверждения, в том числе в составе плана

## ADDED Requirements

### Requirement: Групповое подтверждение плана чтений

Сервис SHALL запрашивать подтверждение один раз на прогон — на весь план чтений, и MUST NOT останавливать прогон повторно на каждом вызове того же плана.

#### Scenario: План из нескольких источников

- **WHEN** план разбора портфеля содержит цены, дивиденды, фундаментал, прогнозы и новости
- **THEN** пользователь получает один запрос подтверждения на весь план и одно решение

#### Scenario: Повторный вопрос в той же сессии

- **WHEN** пользователь задаёт новый вопрос, требующий чтения данных
- **THEN** подтверждение запрашивается заново, ранее данное согласие не переносится

### Requirement: Состав запроса подтверждения по плану

Запрос подтверждения SHALL содержать текст вопроса, перечень планируемых чтений с короткими названиями действий, число запросов и затрагиваемые счёта, без секретов и без полного каталога инструментов.

#### Scenario: Разбор портфеля

- **WHEN** план содержит двадцать чтений по трём счетам
- **THEN** запрос подтверждения перечисляет планируемые чтения по видам данных и указывает число запросов и счетов

#### Scenario: Точечный вопрос

- **WHEN** план содержит одно чтение по одной бумаге
- **THEN** запрос подтверждения содержит название действия и параметры этого чтения

### Requirement: Отказ от плана

При отказе пользователя сервис SHALL не выполнять ни одного чтения плана и MUST сообщить, какие данные не были получены.

#### Scenario: Пользователь отказал

- **WHEN** пользователь отклоняет подтверждение плана
- **THEN** ни один запрос плана не выполняется, а ответ объясняет, что данные не читались, и предлагает подтвердить запрос

### Requirement: Незавершённый сбор при подтверждённом плане

Если часть чтений плана завершилась ошибкой после подтверждения, сервис MUST NOT запрашивать подтверждение заново на те же чтения.

#### Scenario: Ошибка источника после подтверждения

- **WHEN** подтверждённый план частично не выполнен из-за ошибок брокера
- **THEN** ответ формируется по собранным данным и сообщает о недоступных источниках без второго запроса подтверждения
