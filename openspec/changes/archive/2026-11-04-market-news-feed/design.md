# Design

## Context

См. `proposal.md` — Why. Текущее состояние, важное для реализации:

- Граф: `classify → (offTopic | agent ⇄ approve → tools | plan → approve → collect → report)`,
  узлы собираются в `src/agent/graph/build-graph.ts`, маршруты — в `routers.ts`.
- Источники уже абстрагированы: `SourceRegistry` (`src/sources/registry.ts`) умеет
  отдавать общую повестку и повестку по тикерам, кэшировать ленты, изолировать
  отказы и складывать покрытие. Адаптеры: брокер, РБК, Интерфакс, smart-lab
  (включая ленту по тикеру), БКС Экспресс и Т-Банк через RSS-мост.
- Сводка новостей уже есть как инструмент `market__news_digest`
  (`src/tools/thematic/news-digest.ts`): собирает по периодам, дедуплицирует,
  отбрасывает дайджесты (`src/sources/noise.ts`).
- Подтверждения живут в `approval-policy` и применяются к вызовам инструментов
  моделью; ветка `plan → collect` подтверждает план целиком.
- Бюджет прогона (`ToolBudget`) ограничивает вызовы MCP-инструментов; ленты —
  обычные HTTP-запросы, но брокерский источник внутри дергает MCP.

## Goals / Non-Goals

**Goals:**

- Один вопрос — один дешёвый ответ: сводка по четырём периодам без чтения
  портфеля, без подтверждения и без вызовов модели.
- Переиспользовать существующие адаптеры и правила фильтрации: новый источник
  появляется в сводке конфигом, без правки ноды.
- Честные пустоты и покрытие: если за сутки ничего нет — так и написано; если
  источник отказал — он в списке недоступных.

**Non-Goals:**

- LLM-пересказ и «главное за период» — сводка формируется кодом.
- Персонализация под портфель, фильтр «только мои бумаги», уведомления.
- Поиск по произвольной теме («новости про нефть») и полнотекстовый поиск.
- Сохранение сводки как отчёта и выгрузка по `reportId`.


## Decisions

### 1. Терминальная нода `news`, а не вызов инструмента моделью

Ветка `classify → news → END` не проходит через `approve` и `tools`. Альтернатива
— оставить всё на модели (`agent` вызывает `market__news_digest` и пересказывает):
медленнее (2–3 шага модели), дороже и допускает пересказ событий, которых нет в
данных. Детерминированная нода даёт стабильный формат и нулевую стоимость модели.

### 2. Формат ответа — отдельная функция форматирования, а не отчёт

`collectNewsDigest` уже возвращает `periods + coverage + asOf`. Добавляется
`formatNewsFeed(result, options)` в том же модуле: шапка «Новости инвестиционного
рынка», четыре блока с лимитом на период, строка покрытия и время данных.
`formatNewsDigest` остаётся для инструмента модели (у него другая подача —
заголовки периодов без нумерации и с упором на тикеры).

Альтернатива — прогонять сводку через шаблон отчёта: лишний слой (шаблон, движок,
провайдеры) ради четырёх списков; отчёт и новостная сводка — разные сущности.

### 3. Окна периодов и лимиты — конфигурацией

`NEWS_FEED_PERIODS` (по умолчанию `1,7,30,180` дней) и
`NEWS_FEED_MAX_PER_PERIOD` (по умолчанию 5). Спецификация фиксирует четыре
периода как поведение по умолчанию; конфиг позволяет сузить/расширить без
изменения кода. Пустой период не заполняется более старыми публикациями:
фильтрация идёт по времени, а не «до первого непустого».

### 4. Фильтр инвестиционной повестки — расширяемый список правил

Используются два слоя: `isDigestTitle` (уже есть: «утро», «итоги торгов»,
«неделя на рынке») и новый `isOffTopicTitle` (`src/sources/noise.ts`) со
списком спортивных, развлекательных и неэкономических маркеров. Правила — одна
функция над заголовком и аннотацией, чтобы их можно было расширять и тестировать
без ноды. Альтернатива — фильтр по источнику целиком (РБК отдаёт и спорт):
слишком грубо, теряются экономические новости того же источника.

### 5. Классификация `market_news` — правило + модель как фолбэк

Приоритет у детерминированного правила: слова «новости», «что нового на рынке»,
«новости инвестиций» без тикера/компании и без слов про портфель. Модель
используется, если правило не сработало (как сейчас для остальных меток). Это
убирает дрожание: «какие новости за неделю» и «что нового на рынке» должны
попадать в одну ветку всегда.

Пограничные случаи:

- «новости по SBER» → остаётся `data_lookup`/`security_analysis` (новости бумаги
  модель получает инструментом);
- «новости и что делать с портфелем» → `portfolio_review`: есть портфельная часть,
  значит подтверждение и разбор.

### 6. Подтверждения и бюджет

Нода не вызывает MCP-инструменты напрямую, поэтому `approve` не участвует.
Брокерский источник внутри ноды дергает `invest_get_news` — он проходит через
обёртку бюджета прогона: нода открывает прогон (`registry.beginRun`) и уважает
дедлайн, но не запрашивает подтверждение (публичные новости, не данные счёта).
Если брокерский источник отвалился — сводка всё равно собирается из лент.

### 7. Ответ API

В `RunResult` добавляется `report` с `type: "market_news"`, `asOf` и `coverage`
(без `reportId`). Это переиспользует существующий контракт метаданных, не вводя
новых полей верхнего уровня; `intent: "market_news"` отличает ветку.

## Risks / Trade-offs

- [Публичные мосты и ленты нестабильны: 429, таймауты] → ретраи с паузами,
  резервный адрес моста, кэш лент на 5 минут, честное покрытие в ответе.
- [Эвристика «инвестиционности» может отсечь полезную новость] → правила лежат
  в одном файле и покрыты тестами; отсечение работает по заголовку, аннотации и
  дайджест-маркерам, а не по источнику.
- [Лента smart-lab по тикеру не используется в общей повестке] → осознанно: без
  тикеров она не запрашивается, иначе это 10+ лишних запросов.
- [Пользователь ждёт «главное за месяц»] → сводка даёт список с датами и
  источниками; выжимка моделью — отдельное изменение.

## Migration Plan

1. Добавить интент и ноду, оставив прежние маршруты без изменений.
2. Включить по умолчанию (`NEWS_FEED_ENABLED=true`); при отключении новостные
   вопросы уходят прежним маршрутом `data_lookup` — откат без миграций данных.
3. Данные не мигрируются: сводка не сохраняется.

## Open Questions

Нет: спорные решения (границы интента, отсутствие LLM-выжимки, отсутствие
сохранения сводки) зафиксированы выше и в спецификациях.
