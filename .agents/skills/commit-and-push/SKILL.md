# Завершение этапа: проверки, очистка, коммит и push

Выполняется после каждого логически завершённого этапа (пункт `tasks.md`, фикс,
новая возможность). Один этап — один коммит; незавершённое не коммитится.

## 1. Проверки перед коммитом

```bash
npm run build
npm run lint
npm test
npm run test:e2e
npm run eval                # если менялись промпты, маршрутизация, знания
```

Если этап менял поведение модели или промпт — обязателен живой прогон:

```bash
node scripts/ask.mjs "вопрос из задачи" --full --approve
```

Правило: **красный тест — не коммитим.** Тест не ослабляется ради зелёного:
исправляется причина; осознанная смена поведения — отдельный коммит с обновлением
теста и объяснением.

## 2. Очистка временных файлов

Удалить всё, что создано для отладки этапа и не должно попасть в репозиторий:

```bash
git status --short --untracked-files=all
```

Типичные временные артефакты: `*.log`, `*.pid`, `ab.log`, `tmp/`, `report.md`,
`coverage.json`, `health.json`, `sid.txt`, `rid.txt`, `tool-dump.jsonl`, `*.tsbuildinfo`,
`*.md` из `scripts/ask.mjs --save`, `.probe/`, `.browser-profile/`.

Правила:
- временные файлы не коммитятся, а удаляются (`Remove-Item` в PowerShell или `rm`);
- `.env`, `.state/`, `certs/`, `dist/`, `node_modules/` не коммитятся никогда;
- `data/` версионируется (это справочники и знания), `.state/` — нет (это состояние);
- не удалять артефакты, которые нужны другим: `svc.log`/`svc.pid` — только если сервис остановлен.

## 3. Коммит

```bash
git add -A
git commit -m "тип(область): короткое описание" -m "Что изменилось и зачем; чем проверено."
```

Типы: `feat`, `fix`, `docs`, `test`, `refactor`, `chore`.
Область — по модулю: `agent`, `dialogues`, `news`, `knowledge`, `reports`, `observability`, `readme`.

Требования к сообщению:
- первая строка до 72 символов, в повелительном наклонении, без точки;
- в теле: причина изменения и как проверено (`npm test`, `e2e`, `eval`, живой прогон);
- не смешивать несвязанные изменения в одном коммите;
- `git add -A` допустим только после проверки `git status`: в индексе не должно быть
  временных файлов, секретов и живых транскриптов с данными пользователя.

## 4. Push

```bash
git push origin master
```

Если push отклонён (`non-fast-forward`) — `git pull --rebase`, повторить проверки,
затем push. Не использовать `--force` без явного решения пользователя.

## 5. Проверка результата

```bash
git status --short --untracked-files=all    # должно быть пусто
git log --oneline -1                        # коммит на месте
```

Сообщить в ответе: что закоммичено, какие проверки пройдены, что осталось.

## 6. OpenSpec: после каждого этапа tasks.md

1. Отметить выполненный пункт `[x]` в `openspec/changes/<change>/tasks.md`.
2. Выполнить шаги 1–5 этого скилла (проверки → очистка → коммит → push).
3. Когда все пункты закрыты — архивировать изменение скиллом `openspec-archive-change`
   (перенос в `openspec/changes/archive/`, синхронизация спеков), затем коммит и push.

## 7. Что нельзя

- Коммитить с падающими тестами или без прогона `test:e2e`.
- Коммитить `.env`, `.state/`, `certs/`, логи, временные файлы.
- Оставлять после этапа мусор в рабочем дереве.
- Пушить секреты и живые транскрипты с реальными суммами.
- Делать один коммит на несколько несвязанных этапов.
