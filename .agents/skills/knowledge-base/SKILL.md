# База знаний: как писать темы

База знаний — это каталог `data/knowledge/NN-<id>.yaml`. Она подаётся модели в трёх местах:
промпт раздела отчёта (по разделу и секторам), системный промпт агента (по текущему вопросу)
и справочный ответ ветки `knowledge` (модель-эксперт по теме). Слабая тема = поверхностный
ответ, поэтому требования к глубине жёсткие.

## 1. Формат темы

```yaml
version: 1
topics:
  - id: bond-prices                  # уникальный, латиницей
    title: Цена облигации и доходность
    summary: Одно-два предложения — определение, которое цитирует ответ.
    points:                          # 6+ тезисов, каждый — одна строка
      - При росте ставки старые облигации дешевеют
    details:                         # 4+ подраздела, в каждом 4+ тезиса
      - title: Три вида доходности
        points:
          - Купонная доходность считается от номинала
    pitfalls:                        # 3+ частые ошибки
      - Смотреть только на купон
    sections: [verdict, macro]       # разделы отчёта, где тема полезна
    sectors: [финансы]               # секторы брокера (необязательно)
    keywords: [облигация, купон, ytm]
    sources:
      - Т-Инвестиции, «Как формируется цена облигации»
```

Ограничения парсера (`src/shared/parsing/yaml.ts`): YAML-подмножество, каждый тезис — одна
строка без переносов, многострочные блоки не поддерживаются.

## 2. Что делает тему сильной

- **Механизм, а не лозунг.** Не «высокая ставка плохо для акций», а «ставка повышает стоимость
  долга и требуемую доходность, поэтому оценка будущей прибыли снижается».
- **Число с периодом** там, где это иллюстрация: «нефть выросла вчетверо с октября 1973 по
  март 1974».
- **Кто выигрывает, кто проигрывает.** У каждого факта есть адресат: экспортёр, застройщик,
  держатель длинных облигаций.
- **Ограничения и ловушки.** Подраздел `pitfalls` — обязателен, иначе тема учит слишком просто.
- **Где это применимо.** `sections` и `keywords` определяют, когда тема попадёт в промпт.
- **Источник.** Даже конспект должен ссылаться на материал.

## 3. Как добавить тему

1. Файл `data/knowledge/NN-<id>.yaml`, номер — следующий по порядку (порядок задаёт имя).
2. Заполнить `id`, `title`, `summary`, `points` (6+), `details` (4+), `pitfalls` (3+),
   `keywords`, `sources`.
3. Подключить к шаблону `reports/portfolio-review.yaml` в `knowledge: [...]` нужного раздела
   (macro, opinions, conclusion, verdict, tax) — иначе тема не попадёт в отчёт.
4. `npm test -- knowledge` — тест читает реальный каталог и проверяет глубину каждой темы.
5. Проверить живой ответ: `node scripts/ask.mjs "что такое <тема>?" --full`.

## 4. Что нельзя

- Копировать текст статьи: в базу идёт конспект своими словами со ссылкой на источник.
- Делать тему без `details` и `pitfalls` — тест не пропустит, и ответ будет плоским.
- Дублировать `id` (второй файл молча пропускается).
- Писать в тезисах текущие рыночные числа как факт: числа в базе — исторические иллюстрации,
  актуальные значения берутся только из инструментов.
- Забывать про подключение к шаблону — тема будет лежать мёртвым грузом.

## 5. Где тема используется

| Место | Как отбирается |
|---|---|
| промпт раздела отчёта | `knowledge: [...]` в шаблоне + вес по сектору/разделу |
| системный промпт агента | `promptBlock({ question })`: до 4 тем по ключевым словам вопроса |
| ветка `knowledge` | `topicFor(question)` — тема по совпадению ключевых слов; отвечает модель |
| `knowledge__explain` (инструмент) | тот же `topicFor`, но ответ отдаётся как справка |
