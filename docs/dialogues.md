# Корзина диалогов и эталонные ответы

Корзина фиксирует, **как сервис должен отвечать на типовые вопросы**, чтобы не проверять
всё вручную после каждой правки. Один файл — один список кейсов:

```
test/fixtures/dialogues.json      вопросы, ожидаемый маршрут и фрагменты ответа
test/unit/dialogues.spec.ts       проверка маршрута и эталонного ответа
test/e2e/agent-graph.e2e-spec.ts  полный прогон графа для ключевых сценариев
```

## Формат кейса

```json
{
  "id": "buy-plzl",
  "question": "стоит ли покупать полюс золото",
  "resolvedBy": "rule",
  "intent": "portfolio_review",
  "scope": "instrument",
  "target": "PLZL",
  "answer": {
    "mustContain": ["Разбор бумаги PLZL", "• цена за 1 шт.:", "Справочный контекст"],
    "mustNotContain": ["Динамика PLZL за", "Состав портфеля", "% портфеля"]
  }
}
```

| Поле | Смысл |
|---|---|
| `resolvedBy` | `rule` — маршрут решает детерминированное правило; `llm` — метку выбирает модель, проверяем только область |
| `intent` | ожидаемая ветка: `data_lookup`, `security_analysis`, `portfolio_review`, `market_news`, `agent_help`, `knowledge_question`, `off_topic` |
| `scope` / `target` | ожидаемая область разбора и тикер |
| `answer.mustContain` | фрагменты эталонного ответа (отчёт собирается кодом; для разделов модели проверяется заголовок и брифинг) |
| `answer.mustNotContain` | чего в ответе быть не должно (например, одиночной динамики цены) |

Кейсы без `answer` проверяют только маршрут: текст такого ответа пишет модель, и
фиксировать его в тесте нет смысла.

## Ключевое правило: решение по бумаге — это разбор

«Стоит ли покупать X», «продавать или держать X», «перспективы акций X» — это не
точечный вопрос по данным. Такие вопросы уходят в `portfolio_review` с областью
`instrument`: сервис собирает цену, динамику, график, прогноз, дивиденды, профиль и
новости бумаги, показывает справочный блок и даёт сбалансированную оценку с
напоминанием, что это не индивидуальная инвестиционная рекомендация.

Свободный агент (`security_analysis`) в таком случае отвечал одной динамикой цены —
поэтому для вопросов-решений добавлено правило `DECISION_PATTERN` (в
`src/agent/nodes/classify/prompt.ts`), а в промпт агента — требование собирать
несколько источников и помечать суждения как оценку.

## Как прогнать

```bash
npm test -- dialogues      # маршруты и эталонные ответы (15 кейсов)
npm run test:e2e           # полный прогон графа, включая «стоит ли покупать Сбер»
```

## Как добавить кейс

1. Добавьте запись в `test/fixtures/dialogues.json`.
2. Если `resolvedBy: "rule"` — убедитесь, что правило действительно срабатывает
   (иначе тест покажет расхождение).
3. Если нужен эталонный ответ — заполните `mustContain`/`mustNotContain` тем, что
   должно быть в markdown-отчёте.
4. Прогоните `npm test -- dialogues`: расхождения печатаются по id кейса.
