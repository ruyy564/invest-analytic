# Источники данных

Агент берёт данные из нескольких источников. Каждый источник объявляет темы,
которые обслуживает, поэтому новый источник — это адаптер и строка конфигурации,
а не правка графа или шаблона отчёта.

## Три уровня

```
Тематический инструмент (что видит модель)   market__news_digest
   └─ провайдер фактов (что видит шаблон)    news.digest
        └─ источник (откуда данные)          tinkoff │ interfax │ rbc │ smartlab
```

- **Инструмент** — тонкая обёртка: схема аргументов и текст для модели.
- **Провайдер** — превращает данные источников в факты секции отчёта.
- **Источник** — адаптер конкретного происхождения данных.

## Проверенные источники

| id | Что даёт | Адрес | Формат |
|---|---|---|---|
| `tinkoff` | портфель, операции (включая удержанные налоги), новости по тикерам, справочники, прогнозы, сигналы | T-Invest MCP | MCP (JSON) |
| `cbr` | ключевая ставка и история решений | `https://www.cbr.ru/DailyInfoWebServ/DailyInfo.asmx` (метод `KeyRateXML`) | SOAP → XML |
| `interfax` | общие новости | `https://www.interfax.ru/rss.asp` | RSS 2.0 |
| `rbc` | новости экономики и рынков | `https://rssexport.rbc.ru/rbcnews/news/30/full.rss` | RSS 2.0 |
| `smartlab` | мнения сообщества, разборы налогов | `https://smart-lab.ru/rss/` | RSS 2.0 |

Резервные пути для ставки: HTML-таблица `https://www.cbr.ru/hd_base/KeyRate/`
(параметры `UniDbQuery.From`/`To`, дата в формате `дд.мм.гггг`) и сид-файл
`data/key-rate-seed.json`.

Ограничения, о которых отчёт говорит прямо:

- новости брокера отдаются лентой без фильтра по дате — период определяется по времени публикации;
- у ЦБ нет JSON-интерфейса курсов валют со ставкой: `cbr-xml-daily.ru` содержит только валюты;
- сайт ФНС не отдаёт RSS, поэтому изменения налогообложения берутся из лент и словаря терминов.

## Конфигурация

```dotenv
# id источников через запятую: tinkoff | cbr | interfax | rbc | smartlab
SOURCES=tinkoff,cbr,interfax,rbc,smartlab

# live — кэш → SOAP ЦБ → сид → HTML-таблица; seed — только файл; off — без ставки
KEY_RATE_SOURCE_MODE=live
KEY_RATE_SEED_FILE=data/key-rate-seed.json
KEY_RATE_SOAP_URL=https://www.cbr.ru/DailyInfoWebServ/DailyInfo.asmx
KEY_RATE_HTML_URL=https://www.cbr.ru/hd_base/KeyRate/
KEY_RATE_CACHE_TTL_HOURS=24

# ленты, участвующие в сводке новостей
NEWS_SOURCES=interfax,rbc,smartlab
NEWS_SCAN_PAGES=3
NEWS_DIGEST_MAX_ITEMS=10

# словарь налоговых терминов
TAX_KEYWORDS_FILE=data/tax-keywords.yaml
```

Адрес конкретной ленты можно переопределить переменной `NEWS_<ID>_URL`
(например, `NEWS_INTERFAX_URL`), не меняя код.

## Как добавить источник

1. Добавьте адаптер в `src/sources/`:
   - для RSS/Atom/JSON достаточно `createFeedSource({ id, url, format, topics, mapping })`;
   - для нового типа данных — реализуйте соответствующий контракт из `src/sources/types.ts`.
2. Зарегистрируйте id в `SOURCES` (и в `FEED_DEFAULTS`, если это лента).
3. Если источник должен попасть в отчёт — добавьте его тему в провайдер фактов и,
   при необходимости, секцию в шаблон `reports/portfolio-review.yaml`.

Тест из `test/unit/sources.spec.ts` повторяет этот сценарий: новая лента
подключается записью в реестре и попадает в сводку без правок кода.

## Кэш и деградация

- Медленноменяющиеся данные (ставка, справочники) кэшируются в SQLite с TTL
  `*_CACHE_TTL_HOURS`; котировки, новости и прогнозы не кэшируются.
- Отказ одного источника не прерывает сбор: причина попадает в `coverage`
  и в отчёт строкой «Недоступные источники».
- Если данных нет ни в одном источнике, инструмент отвечает «нет данных»
  с причиной, а не пустым списком.
