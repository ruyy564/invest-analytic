# Источники данных

Агент берёт данные из нескольких источников. Каждый источник объявляет темы,
которые обслуживает, поэтому новый источник — это адаптер и строка конфигурации,
а не правка графа или шаблона отчёта.

## Три уровня

```
Тематический инструмент (что видит модель)   market__news_digest
   └─ провайдер фактов (что видит шаблон)    securities.detail
        └─ источник (откуда данные)          tinkoff │ interfax │ rbc │ smartlab
```

- **Инструмент** — тонкая обёртка: схема аргументов и текст для модели.
- **Провайдер** — превращает данные источников в факты секции отчёта.
- **Источник** — адаптер конкретного происхождения данных.

## Новости: только по бумагам

В отчёт попадают новости, которые относятся к бумаге, а не общая лента. Механика:

- `tinkoff` умеет искать по тикеру (`invest_get_news` с `instrumentId`) — объявляет
  `supportsTickerQuery: true`;
- ленты (`interfax`, `rbc`, `smartlab`) поиска по тикеру не имеют, но объявляют
  `supportsMatcherQuery: true` и фильтруют заголовки по подстрокам (`matchers` —
  тикер и название компании из позиций);
- общий поток лент в сводку не попадает: спорт, политика и кино не влияют на портфель;
- общие обзоры брокера («итоги торгов», «суммарные итоги») отбрасываются: брокер
  помечает их всеми тикерами, к бумаге они не относятся.

Если по бумаге публикаций нет — отчёт так и пишет: «новостей по бумаге нет».

### Telegram не используется

У БКС и Т-Инвестиций нет публичного RSS (проверено 05.11.2026):
`bcs-express.ru/rss`, `/rss/news`, `/rss.xml` отдают HTML лендинга или `403`
даже с браузерным User-Agent, а `tbank.ru/invest/research` и `tinkoff.ru/invest` —
HTML без `<link rel="alternate" type="application/rss+xml">`. Вместо мостов
Telegram читаются сами страницы:

- **`rbc_quote`** — `https://www.rbc.ru/quote`: новости рынка лежат в
  `<script id="__NEXT_DATA__" type="application/json">` (`props.pageProps.materials`
  и `newsfeed`); у материала есть `header`, `anons`, `publishDate` и `tickers`.
- **`tbank_research`** — `https://www.tbank.ru/invest/research/`: идеи аналитиков
  лежат в SSR-состоянии Tramvai (`<script type="application/json">` →
  `growth-research-portal*.stores.tradingIdeas.ideas`), у идеи есть `title`,
  `date`, `description` и `tickers`.

Разбор HTML — в `src/shared/parsing/html.ts` (`jsonScriptsOf`), адаптеры — рядом с лентами
(`src/capabilities/news/sources/rbc-quote.ts`, `tbank-research.ts`). Оба источника объявляют
`supportsTickerQuery`, поэтому по бумаге отдают только её новости (по `tickers`).

Объём новостей добирают деловые RSS: Ведомости, Коммерсантъ (раздел «Финансы»),
ТАСС (раздел «Экономика») и Финам. По бумаге также работают `smartlab_tag`
и брокер (`invest_get_news`).

### Сводка новостей рынка (ветка `news`)

Отдельная ветка графа отвечает на вопросы вида «какие последние новости в мире
инвестиций»: собирает общую повестку всех включённых источников и раскладывает
её по окнам времени — по умолчанию сегодня (24 часа) и за неделю. Портфель
не читается, подтверждение не запрашивается, модель не вызывается: ответ
собирается кодом.

- окна и лимит задаются `NEWS_FEED_PERIODS` (дни через запятую, по умолчанию
  `1,7`) и `NEWS_FEED_MAX_PER_PERIOD` (по умолчанию 8);
- пул кандидатов намеренно шире выдачи (в 8 раз больше лимита на окно): иначе
  в сводку попадают только самые свежие посты двух-трёх лент, а Ведомости,
  Коммерсантъ и Финам не видны вовсе;
- публикация попадает только в самое свежее окно, куда укладывается по дате;
- общие сводки («утренняя сводка», «итоги торгов») и нерелевантная повестка
  (спорт, развлечения, происшествия, гуманитарные «акции») отбрасываются;
- пустые окна не показываются: если новостей нет ни в одном окне, ответ —
  одна строка «За выбранный период инвестиционных новостей нет»;
- недоступный источник перечисляется в ответе с причиной, остальные источники
  продолжают собираться.

Выключить ветку и вернуть прежний маршрут: `NEWS_FEED_ENABLED=false`.

### Как новости привязываются к бумаге
1. `smartlab_tag` — лента smart-lab **по тикеру** (`/rss/tag/SBER`): основной источник
   новостей бумаги, там разборы отчётности, торговые планы и идеи.
2. Брокер: `invest_get_news` по тикеру (`supportsTickerQuery`).
3. Остальные ленты: заголовок и аннотация проверяются на подстроки — тикер,
   название из позиции и алиасы из `data/ticker-aliases.yaml` («Сбер», «ЛУКОЙЛ»,
   «Полюс», «Россети Московский регион»). Файл расширяется без правки кода.
4. `rbc_quote` и `tbank_research` отдают новости по тикеру напрямую: у материалов
   есть список `tickers`, поэтому в разбор бумаги попадают только её публикации.
5. Общие сводки («утренний дайджест», «итоги торгов», «неделя на рынке»,
   «корпоративные события») отбрасываются: бумага в них упоминается, но новостью
   это не является.

## Сырьевой фактор: цены металлов

Для бумаг, чья выручка зависит от металла (`PLZL`, `POLY` — золото), в разбор
бумаги добавляется строка «сырьё: золото 10 187,57 ₽/г на 03.11.2026 (ЦБ РФ)».

| id | Что даёт | Адрес | Формат |
|---|---|---|---|
| `cbr` (metals) | учётные цены золота, серебра, платины, палладия, ₽/г | `https://www.cbr.ru/scripts/XML_metall.asp?date_req1=…&date_req2=…` | XML (windows-1251) |

- источник включён вместе с `cbr` и кэширует снимок в памяти процесса на 6 часов;
- карта «бумага → металл» живёт в `src/capabilities/market/commodities/commodity.links.ts`;
- инструмент модели — `macro__commodities`, группа плана `commodities`;
- если металл для бумаги неизвестен или ЦБ не ответил, строка просто не выводится
  (никаких «недоступно» в разборе бумаги).

Резервные пути для ставки: HTML-таблица `https://www.cbr.ru/hd_base/KeyRate/`
(параметры `UniDbQuery.From`/`To`, дата в формате `дд.мм.гггг`) и сид-файл
`data/key-rate-seed.json`.

Ограничения, о которых отчёт говорит прямо:

- новости брокера отдаются лентой без фильтра по дате — период определяется по времени публикации;
- у ЦБ нет JSON-интерфейса курсов валют со ставкой: `cbr-xml-daily.ru` содержит только валюты;
- сайт ФНС не отдаёт RSS, поэтому изменения налогообложения берутся из лент и словаря терминов.

## Конфигурация

```dotenv
# id источников через запятую: tinkoff | cbr | interfax | rbc | smartlab
# | smartlab_tag | rbc_quote | tbank_research | vedomosti | kommersant | tass | finam
# | news_extra (ленты из NEWS_EXTRA_FEEDS_FILE)
SOURCES=tinkoff,cbr,interfax,rbc,smartlab,smartlab_tag,rbc_quote,tbank_research,vedomosti,kommersant,tass,finam,news_extra

# live — кэш → SOAP ЦБ → сид → HTML-таблица; seed — только файл; off — без ставки
KEY_RATE_SOURCE_MODE=live
KEY_RATE_SEED_FILE=data/key-rate-seed.json
KEY_RATE_SOAP_URL=https://www.cbr.ru/DailyInfoWebServ/DailyInfo.asmx
KEY_RATE_HTML_URL=https://www.cbr.ru/hd_base/KeyRate/
KEY_RATE_CACHE_TTL_HOURS=24

# ленты новостей и мнений (RSS 2.0) + HTML-страницы брокеров; Telegram не используется
NEWS_SOURCES=interfax,rbc,smartlab,smartlab_tag,rbc_quote,tbank_research,vedomosti,kommersant,tass,finam
NEWS_SCAN_PAGES=3
NEWS_DIGEST_MAX_ITEMS=10
# окна сводки в днях: сегодня и неделя
NEWS_FEED_PERIODS=1,7
NEWS_FEED_MAX_PER_PERIOD=8
# дополнительные ленты: файл со списком источников (id, url, format, topics)
NEWS_EXTRA_FEEDS_FILE=data/news-sources.yaml
# индекс публикаций и фоновый сбор: история шире сетевого окна лент
NEWS_INDEX_ENABLED=true
NEWS_INDEX_TTL_DAYS=30
NEWS_CRAWLER_ENABLED=true
NEWS_CRAWLER_INTERVAL_MIN=15
NEWS_CRAWLER_MAX_ITEMS=60
# бумаги для фонового сбора (список тикеров)
NEWS_WATCHLIST_FILE=data/watchlist.yaml

# словарь налоговых терминов и алиасы эмитентов для поиска новостей
TAX_KEYWORDS_FILE=data/tax-keywords.yaml
TICKER_ALIASES_FILE=data/ticker-aliases.yaml
```

Адрес конкретной ленты можно переопределить переменной `NEWS_<ID>_URL`
(например, `NEWS_INTERFAX_URL`), не меняя код.

## Индекс публикаций и фоновый сбор

Ленты отдают только последние дни — назад «за полгода» они не отвечают. Поэтому
собранное складывается в SQLite (`news_items`, `news_texts` в файле
`STATE_SQLITE_PATH`):

- `NewsCrawlerService` (`src/transports/mcp/news-crawler.service.ts`) раз в
  `NEWS_CRAWLER_INTERVAL_MIN` минут собирает общую повестку, отраслевые факторы
  (нефть, курс, ставка, санкции) и новости по бумагам из `NEWS_WATCHLIST_FILE`
  (`data/watchlist.yaml`), кладёт публикации в индекс и чистит записи старше
  `NEWS_INDEX_TTL_DAYS`. Первый проход — сразу после старта.
- `news__search` сохраняет всё, что нашёл, и дополняет выдачу историей из индекса:
  запрос «за 90 дней» работает, даже если лента помнит только неделю.
- Текст статьи кэшируется по ссылке (`news_texts`): одна и та же статья не
  скачивается повторно ни в этом прогоне, ни в следующих.
- `NEWS_INDEX_ENABLED=false` — работать без индекса (как раньше, только ленты).
  При `STATE_BACKEND=memory` индекс живёт в памяти процесса.

## Как добавить источник

0. **Без правки кода** — добавить ленту в файл `data/news-sources.yaml`
   (путь меняется `NEWS_EXTRA_FEEDS_FILE`), а в `SOURCES` включить `news_extra`:

   ```yaml
   - id: cbr
     url: https://www.cbr.ru/rss/eventrss
     format: rss
     topics: [news, macro]
   ```

   Форматы: `rss`, `atom`, `json`; темы: `news`, `market`, `macro`, `tax`.
   Файла нет или он пуст — поведение не меняется. Так подключается любой
   отраслевой источник: ЦБ, ИР-страницы компаний, отраслевые ленты.
1. Адаптер в `src/capabilities/news/sources/` — если нужен новый тип данных:
   - для RSS/Atom/JSON достаточно `createFeedSource({ id, url, format, topics, mapping })`;
   - для HTML-страниц реализуйте `NewsSourceAdapter` из `src/capabilities/news/news.types.ts`.
2. Зарегистрируйте id в `SOURCES` (и в `FEED_DEFAULTS`, если это лента).
3. Если источник должен попасть в отчёт — добавьте его тему в провайдер фактов и,
   при необходимости, секцию в шаблон `reports/portfolio-review.yaml`.

Тест из `test/unit/sources.spec.ts` повторяет этот сценарий: новая лента
подключается записью в реестре и попадает в сводку без правок кода.

## Тематические новости

Вопрос «какие новости по криптовалютам» — это не общая повестка: без фильтра
сводка отвечает спортом и криминалом. Тема определяется детерминированно по
словарю (`src/capabilities/news/topics.ts`) и передаётся в сбор как фильтр:

- темы: `crypto` (криптовалюты), `oil`, `metals`, `rate`, `sanctions`, `currency`;
- совпадение ищется по заголовку и аннотации; латинские слова (`BTC`, `ETH`) —
  только целым словом, кириллица — подстрокой (падежи);
- для темы инвестиционный маркер не требуется — фильтр по словам темы строже;
- новые темы и слова добавляются строкой в список, без правки сборки.

Криптовалютные ленты (проверены живьём): `forklog`, `incrypted`,
`ru.investing.com`, `cryptocurrency.tech`, `cointelegraph`, `coindesk` —
подключены через `data/news-sources.yaml`.

Заголовки спорта и криминала отбрасываются в любом режиме: `news.filters.ts`
(`OFF_TOPIC_TITLE`) знает про фигурное катание, медали, Гран-при, мошенников,
похищения, аресты и следствие.

## Рыночные факторы числами

Причины движения цены — это не только заголовки: у них есть измеримые факторы.
Инструмент `market__factors` отдаёт значение и изменение за период:

- нефть Brent — индекс `RUCBRNCP`;
- доллар и юань к рублю — `USD000UTSTOM`, `CNYRUB_TOM`;
- ключевая ставка ЦБ — источник ставки (live → кэш → сид → HTML), с датой решения.

Читаются дневные свечи за `days` (по умолчанию 30 дней), изменение считается по
первой и последней точке; недоступный фактор просто пропускается. Это публичные
рыночные значения — бумаги и суммы пользователя инструмент не читает, поэтому
подтверждение для него не требуется (`approval-rules.ts`).

- Ленты отдают аннотацию публикации (первые ~240 символов в ответе `news__search`)
  и полные аннотации внутри сбора; разметка чистится `stripMarkup`, поэтому
  модель видит текст, а не HTML.
- Параметр `fullText: true` у `news__search` **дочитывает первые статьи целиком**
  (`src/capabilities/news/sources/article.ts`): скрипты, стили и навигация
  отбрасываются, из абзацев собирается текст до 1 200 символов. Это ключ к
  причинам: в заголовке «Лукойл вырос», а нефть, дивиденды и сделка — в тексте.
- Параметр `factors: true` добавляет блок «Факторы»: запрос по драйверам сектора
  бумаги и общим рыночным факторам (`data/company-profiles.yaml` →
  `sectors[].factors`, `marketFactors`). Так находятся причины, в которых бумага
  не названа: «выборы в США обвалили цены на нефть», «выплаты по демпферу выросли».
  Совпадения считаются по заголовку и взвешиваются: драйвер сектора важнее общего
  рынка, длинная формулировка — важнее короткой подстроки.
- На вопрос о причине узел агента сам запрашивает окно до 90 дней и до 12
  публикаций по бумаге, статьи целиком и блок факторов.

## Календарь заседаний ЦБ

Даты решений по ставке — файл-данные `data/cb-meetings.yaml`: ЦБ публикует план
заранее, а парсинг календаря на сайте ломается от редизайна страницы. Формат:

```yaml
updatedAt: 2026-11-01
source: https://www.cbr.ru/calendar/
meetings:
  - date: 2026-12-18
    type: опорное
  - date: 2027-02-12
    type: предварительное
```

Локальный инструмент `macro__cb_meetings` берёт только будущие даты и печатает их с
датой актуальности плана (`план на …`); битые строки пропускаются, отсутствие файла
не ломает ответ — «дат в данных не найдено». Как и `market__factors`, это публичные
данные, подтверждение не требуется (`approval-rules.ts`).

Путь задаётся `CB_MEETINGS_FILE` (по умолчанию `data/cb-meetings.yaml`).

## Кэш и деградация

- Медленноменяющиеся данные (ставка, справочники) кэшируются в SQLite с TTL
  `*_CACHE_TTL_HOURS`; котировки, новости и прогнозы не кэшируются.
- Отказ одного источника не прерывает сбор: причина попадает в `coverage`
  и в отчёт строкой «Недоступные источники».
- Если данных нет ни в одном источнике, инструмент отвечает «нет данных»
  с причиной, а не пустым списком.
