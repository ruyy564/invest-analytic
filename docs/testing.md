# Тестирование: что проверяется и по каким правилам

Проверки делятся на четыре уровня: unit, e2e, оценка качества (eval) и живые проверки.
Тесты не ходят в сеть и не зависят от времени: брокер и модель подменяются фикстурами.

## Уровни и команды

| Команда | Уровень | Что проверяет | Когда обязательна |
|---|---|---|---|
| `npm run build` | типы | строгая компиляция ESM, ошибки типов | всегда |
| `npm run lint` | стиль | eslint по `src` и `test` | всегда |
| `npm test` | unit | домен, узлы, маршрутизация, инструменты, источники, отчёты | всегда |
| `npm run test:e2e` | e2e | реальный Nest-граф на фейковом MCP и скриптовой модели | всегда |
| `npm run eval` | качество | кейсы диалогов на записанных ответах, `pass@k`/`pass^k` | после правки промптов, маршрутизации, знаний |
| `npm run eval:live` | качество | те же кейсы на живом сервисе | перед релизом поведения |
| `npm run record:transcripts` | данные | перезапись эталонных ответов | когда формат ответа изменился намеренно |
| `npm run replay -- <runId>` | разбор | транскрипт прогона из журнала | при разборе инцидента |
| `npm run smoke:mcp` | интеграция | живое подключение к T-Invest MCP | при смене токена/сети/TLS |
| `npm run studio:check` | граф | граф собирается и виден в Studio | при изменении топологии |

## Что именно тестируется

| Область | Файлы тестов | Что фиксируется |
|---|---|---|
| Маршрутизация и guard | `test/unit/routing-guard.spec.ts` | сценарий, область, наследование темы, «не отказ» для экономики |
| Узел агента | `test/unit/agent-node.spec.ts` | данные текущего прогона, отказ vs факты, промпт с базой знаний |
| Причины движения | `test/unit/cause-answer.spec.ts` | факты без интерпретации, «причина не установлена» |
| Отбор инструментов | `test/unit/tool-scope.spec.ts` | база + расширения по теме, префиксы MCP |
| Поиск эмитента | `test/unit/discovery.spec.ts` | кандидаты из вопроса, стемминг, защита от повторов |
| Выбор инструмента | `test/unit/instrument-facade.spec.ts` | акция важнее облигации, точный тикер важнее вида |
| Знания | `test/unit/knowledge.spec.ts`, `knowledge-node.spec.ts` | формат тем, глубина, отбор, ответ моделью |
| Новости | `news-feed`, `news-crawler`, `news-index`, `news-company-filter`, `news-factors` | периоды, фильтры, офтоп, омонимы компаний |
| Отчёты | `test/unit/report-interpretation.spec.ts`, `planner`, `conclusion`, `analytics-brief` | секции, шаблон, интерпретация, нейтрализация брифинга |
| MCP | `test/unit/mcp-registry.spec.ts`, `tool-catalog`, `tool-contracts` | allowlist, именование, бюджет, каталог |
| Подтверждения | `test/unit/approval-policy.spec.ts` | что требует подтверждения, что нет |
| Состояние и прогоны | `run-events`, `observability`, `state` | события, маскирование, журнал |
| Кейсы eval | `test/unit/eval-cases.spec.ts` | схема кейса, грейдеры, теги `required` |

E2E (`test/e2e/`) собирает настоящее приложение: `AppModule` + `e2eToolCatalog`
(фейковые MCP-инструменты с реалистичными JSON) + `IntentAwareModel`/`ScriptedChatModel`
(заранее заданные ответы). Проверяются HTTP-контракты, ветки графа, подтверждения,
рестарт состояния и «вопрос не получает прошлый отчёт».

## Правила

1. **Новое поведение — новый тест.** Изменение без теста не считается готовым.
2. **Регрессия из реального провала.** Сначала кейс, воспроизводящий ошибку
   (вопрос пользователя), потом фикс — тест должен упасть до и пройти после.
3. **Никакой сети и времени в тестах.** Брокер — фикстуры, модель — скриптовая,
   `now` передаётся аргументом. Тест не должен зависеть от даты запуска и порядка.
4. **Русские регексы — без `\w` и `\b`.** В JS они не работают с кириллицей;
   используйте `[а-яё]` и явные границы `(?![а-яё])`.
5. **Промпт меняется — кейс в eval.** Любая правка `reports/prompts/*` или системного
   промпта агента сопровождается кейсом в `test/eval/cases` и живым прогоном.
6. **Кейс eval — это задача с грейдерами.** `answer.mustContain/mustNotContain`,
   `sections`, `minNumbers`, `expectedTools`; тег `required` означает «должно проходить
   всегда». Общий прогон обязан давать `pass@k = 100 %` на `required`.
7. **Транскрипты.** Офлайн-кейс берёт ответ из `transcript` в JSON или из
   `test/eval/transcripts/<id>.txt`. Живые транскрипты с реальным портфелем не
   коммитятся (исключение — `analytics-brief-sber.txt` на фикстурах).
8. **E2E не заменяет живой прогон.** Скриптовая модель не покажет реакцию GigaChat:
   после правки промпта нужен `node scripts/ask.mjs "…" --full --approve`.
9. **Тест не ослабляется ради зелёного.** Если тест упал — исправляется причина,
   а не ожидание. Осознанная смена поведения — отдельный коммит с обновлением теста
   и объяснением в сообщении.
10. **Имена описывают поведение.** `it('короткая реплика продолжает тему')`, а не
    `it('works')`. `describe` — по-русски, как в остальном проекте.
11. **Изоляция файлов.** Временные каталоги — `mkdtemp`; состояние e2e — `STATE_BACKEND=memory`.
12. **Перед коммитом** — `build`, `lint`, `test`, `test:e2e`, `eval`; после правки
    поведения — ещё и живой прогон.

## Кейс оценки: как выглядит

```json
{
  "id": "regression-money-advice",
  "question": "стоит ли покупать квартиру в ипотеку сейчас?",
  "resolvedBy": "rule",
  "intent": "data_lookup",
  "scope": "portfolio",
  "trials": 2,
  "tags": ["required", "regression", "advice"],
  "answer": {
    "mustNotContain": ["вне моей компетенции", "Не понял"],
    "minNumbers": 0
  },
  "transcript": "…записанный ответ…"
}
```

`trials` — сколько раз прогнать кейс; `pass@k` — доля кейсов, где хотя бы одна
попытка прошла; `pass^k` — доля кейсов, где прошли все попытки (стабильность).

## Что не покрыто

- Реальная модель: качество формулировок проверяется живым прогоном и `eval:live`,
  а не unit-тестами.
- Сеть и брокер: `smoke:mcp` — единственная проверка живого MCP; в тестах его нет.
- Внешние сайты новостей: парсеры проверяются фикстурами (`test/fixtures/golden`),
  изменения вёрстки ловятся только живым прогоном.
