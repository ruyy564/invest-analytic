# Аналитика в формате инвест-дома: аудит и план

Коротко: данные и структура у нас есть, но ответ пока «факты + пересказ», а не
аналитика. Ниже — что умеет формат БКС / «Деньги не спят», что у нас уже есть,
чего не хватает и в каком порядке закрываем.

## Формат инвест-дома (планка)

1. Цена и движение: значение, % за 1/7/30/180 дней, минимум/максимум с датами.
2. Что влияет на инструмент и эмитента: факторы (нефть, курс, ставка, санкции,
   отчётность, дивиденды, регулирование) и направление влияния.
3. Что происходит сейчас: свежие публикации с датой и источником + числа по рынку.
4. Что хорошо / нейтрально / плохо — по фактам, а не по настроению.
5. Чего ждём: календарь событий (отчёты, дивидендные отсечки, заседания ЦБ,
   погашения, оферты).
6. Как это может сыграть на цене: два сценария с условиями.
7. Что делать в этой ситуации — рамка решения и что проверить; без индивидуальной
   рекомендации и без обещаний доходности.
8. Ограничения: чего в данных нет.

## Что есть у нас

| Блок | Что есть | Где |
|---|---|---|
| Цена и динамика | 1/7/30/180 дней, график 90 дней, минимум/максимум с датами | `securities.detail`, свечи |
| Мнения аналитиков | цель, потенциал, рекомендация консенсуса | `securities.opinions`, `invest_get_forecast` |
| Фундаментал | P/E, P/B, ROE, долг; нули брокера считаются «нет данных» | `invest_get_asset_fundamentals` (план, группа `fundamentals`) |
| Дивиденды | размер, доходность, даты отсечки и выплаты | `invest_get_share_dividends` |
| Инсайдеры | сделки, суммы, роли | `invest_get_insider_deals` |
| Факторы сектора | драйверы и чувствительность к курсу/ставке | `data/company-profiles.yaml` |
| Факторы числами | Brent, USD/RUB, CNY/RUB, ключевая ставка с изменением | `market__factors` (план, группа `market_factors`) |
| Новости | публикации по бумаге и по факторам, с датой и источником | `news__search`, индекс |
| Календарь событий | отчёты эмитента, дивидендные отсечки, заседания ЦБ, погашения | `invest_get_instrument_reports`, `macro__cb_meetings`, `data/cb-meetings.yaml` |
| Сценарии | два сценария с условиями в тексте модели, факты — кодом | `conclusion`, `analytics.drivers` / `analytics.scorecard` / `analytics.calendar` |

## Пробелы и что делаем

**P1. Данные, которых нет в плане сбора — сделано**

- `invest_get_instrument_reports` (даты отчётов) → секция «Чего ждём»
  (`analytics.calendar`): последняя публикация и ожидаемая следующая дата,
  посчитанная по периодичности и помеченная как (оценка).
- `invest_get_asset_fundamentals` → строка `фундаментал` в брифинге и блок
  «Хорошо, нейтрально, плохо»: P/E, P/B, ROE, долг; нули брокера не выдаются за
  нулевые значения, а считаются отсутствием данных.
- Календарь ЦБ: `data/cb-meetings.yaml` + локальный инструмент `macro__cb_meetings`
  (файл-данные, без парсинга сайта).

**P2. Секции отчёта под формат — сделано**

- «Что влияет на бумагу» (`analytics.drivers`): драйверы сектора
  (`company-profiles`) + факторы числами (`market__factors`) + направление влияния
  из чувствительности сектора, каждая трактовка помечена (оценка).
- «Хорошо, нейтрально, плохо» (`analytics.scorecard`): код сравнивает потенциал до
  цели, дивидендную доходность со средней за 5 лет, ROE и долг с порогами
  (`SCORE_THRESHOLDS`), модель только трактует.
- «Чего ждём» (`analytics.calendar`): даты отчётности, отсечек, заседаний ЦБ и
  погашений; пустой календарь печатает «дат в данных нет».
- «Как это может сыграть на цене»: два сценария с условиями в промпте `conclusion`,
  без целевых цен, которых нет в брифинге.

**P3. Качество**

- Рубрика судьи (`src/eval/judge.ts`) расширяется осями «что влияет», «хорошо/плохо/
  нейтрально», «чего ждём», «сценарии»; корзина `analytics.json` проверяет разделы и
  минимальное число цитат/чисел.
- Каждый реальный дефект ответа становится кейсом корзины с тегом `required`.

## Как понять, что стало лучше

1. `npm test` — контракты и поведение (быстро).
2. `npm run test:e2e` — корзины поведения: тема новостей, причины, разбор бумаги.
3. `npm run eval` — корзины кейсов (структура, цитаты, числа) на записанных ответах.
4. `npm run eval -- --mode judge` — оценка по рубрике (нужен ключ LLM).
