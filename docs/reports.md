# Шаблоны отчётов

Логика отчёта живёт в файле-шаблоне, а не в коде: состав, порядок, пороги и
периоды меняются правкой YAML. Код остаётся только за поставщиков фактов
(`src/report/providers/`) и поставщиков данных (`src/sources/`).

## Где что лежит

```
reports/portfolio-review.yaml        шаблон: секции, пороги, периоды
reports/prompts/interpretation.md    промпт для секций, которые пишет модель
src/report/template.ts               схема и загрузка шаблона
src/report/engine.ts                 сборка отчёта по шаблону
src/report/providers/*.ts            поставщики фактов (имя = provider в шаблоне)
```

## Схема шаблона

```yaml
id: portfolio-review        # обязателен
version: 2                  # попадает в отчёт как templateVersion
periods: [1d, 7d, 30d, 180d]  # только эти значения
thresholds:
  concentration_high: 0.50  # доля крупнейшей позиции → «высокая»
  concentration_medium: 0.25
  min_class_share: 0.05     # порог «класс представлен»
sections:
  - id: table               # обязателен, уникален
    title: Состав портфеля
    provider: portfolio.table      # обязателен, должен быть в реестре
    render: table           # table | distribution | list | kpi | text
    params: { max: 12 }     # свободные параметры секции
    interpret: false        # true — секцию формулирует модель
    knowledge: [reporting]  # темы базы знаний, обязательные для секции
```

`scopes` ограничивает разборы, где секция нужна; `knowledge` добавляет темы базы
знаний к автоматическому отбору по разделу и секторам (темы из шаблона всегда идут
первыми, объём блока по-прежнему ограничен `KNOWLEDGE_MAX_CHARS`). `optional: true`
означает «секция необязательна»: если провайдер не вернул фактов (например, база знаний
выключена), секция не попадает в отчёт — без «Данных нет» и без `partial`.

## Область разбора

Один и тот же граф собирает три вида разбора — область определяется по вопросу:

| Вопрос | scope | Что в отчёте |
|---|---|---|
| `проанализируй мой портфель` | `portfolio` | все счета, полный набор секций |
| `разбери счёт Портфельное инвестирование` | `account` | только этот счёт: состав, структура, концентрация, налоги, пробелы |
| `разбери бумагу SBER` / `разбери Сбер` | `instrument` | только эта бумага: цена за 1/7/30/180 дней, прогноз, дивиденды, её новости, оценка сектора |

Секции с `scopes` показываются не во всех разборах: `structure`, `concentration`,
`tax`, `gaps` помечены `scopes: [portfolio, account]` — в разборе одной бумаги они
только шумят. Список областей в секции необязателен: без него секция общая.

Определение области — правило (`src/agent/scope.ts`): номер/название счёта после
слова «счёт», тикер рядом с «бумага/акции/по» или название компании из
`data/ticker-aliases.yaml`. Модель для этого не используется.

## Секции отчёта по умолчанию

| id | Что показывает | provider |
|---|---|---|
| `table` | бумага, сектор, доля, цена за штуку, стоимость, спарклайн за 90 дней, изменение за 180 дней, мнение аналитиков (только портфель и счёт) | `portfolio.table` |
| `macro` | экономический цикл и рынок: ставка ЦБ, что она значит для классов активов (тема `cycles`) | `macro.context` (модель) |
| `marketnews` | фон рынка: до пяти заголовков общей сводки новостей за неделю; секция необязательная | `market.news` |
| `securities` | по каждой бумаге: цена за штуку, динамика за 1/7/30/180 дней, спарклайн, прогноз, дивиденды, её новости (тема `reporting`) | `securities.detail` |
| `opinions` | оценка каждой бумаги и её сектора (тема `multiples`) | `securities.opinions` (модель) |
| `conclusion` | вывод по бумаге: разбор «за и против», риски, что проверить, сценарии (темы `reporting`, `multiples`, `strategies`, `sector-dependencies`); только разбор бумаги | `securities.conclusion` (модель) |
| `structure` | разрезы: класс, сектор, валюта, эмитент | `portfolio.structure` |
| `exposure` | экспортёры, внутренний рынок, импортёры: доли и чувствительность к курсу и ставке (тема `trade-balance`) | `portfolio.exposure` |
| `concentration` | крупнейшая позиция, топ-3, уровень концентрации | `portfolio.concentration` |
| `tax` | удержанные налоги и изменения налогообложения (тема `taxes`) | `tax.context` |
| `gaps` | классы и секторы ниже порога | `portfolio.gaps` |
| `verdict` | диверсификация, тип стратегии, что менять (тема `strategies`); только портфель и счёт | `facts.brief` (модель) |

**Разбор бумаги не читает портфель.** Вопрос «разбери Полюс» собирает только данные бумаги:
цена и свечи, прогноз, дивиденды, облигационные события, справочник сектора и новости по
тикеру. Ни счета, ни позиции, ни стоимость портфеля не запрашиваются, поэтому в ответе нет
ни «Состава портфеля», ни «Итога по портфелю», ни налогов и пробелов — только карточка
бумаги и оценка её сектора. Секции `table` и `verdict` помечены `scopes: [portfolio, account]`.

Одна и та же новость может относиться к нескольким бумагам (например, «выросли VK,
М.Видео и Самолет»): в разделе `securities` она показывается только в первой карточке,
а у остальных бумаг строка говорит «общие с другими бумагами портфеля (см. выше)».
Новости брокера по тикеру дополнительно фильтруются по упоминанию бумаги (тикер, название,
алиасы): общий поток «рынок акций РФ вырос» в карточку не попадает.

График — спарклайн из свечей (`src/report/sparkline.ts`). Свечи запрашиваются за 365 дней,
а на графике и в диапазоне цен показываются последние 90 дней: старые экстремумы не
растягивают шкалу и не искажают форму движения.

### Что показывает карточка бумаги

| Строка | Источник данных | Пример |
|---|---|---|
| цена за 1 шт. | `invest_get_market_values` | `1 400,00 RUB` |
| динамика 1/7/30/180 дней | `invest_get_candles` | `30 дней +11,33 %` |
| график | свечи за 180 дней | `▁▁▃▂▄▄▆█ (1 180 — 1 400 RUB)` |
| аналитики | `invest_get_forecast` | `покупать, цель 1 408,80, потенциал +30,86 %` |
| дивиденды | `invest_get_share_dividends` | `ближайшая выплата — 37,64 RUB, доходность 13,49 %, отсечка 2026-07-20, выплата 2026-08-04, раз в год; всего выплат 6` |
| инсайдеры | `invest_get_insider_deals` | `2025-12-11 продажа, 216 732 шт., по 307,19 RUB, подконтрольная эмитенту организация` |
| облигация | `invest_get_bond` + `bond_events` + `bond_accrued` | `ОФЗ, купон 2 раз в год, ставка ≈ 7,1 % (оценка), погашение 2041-05-15, НКД 30,34 RUB, ближайший купон 2026-12-02` |
| профиль | `data/company-profiles.yaml` | `экспортёр, валютная выручка около 85 %` |
| чувствительность и драйверы | `data/company-profiles.yaml` | `курс растёт — в плюс, ставка растёт — в минус; драйверы: цены металлов, курс, пошлины` |
| сырьё | ЦБ РФ (учётные цены металлов) | `золото 10 187,57 ₽/г на 03.11.2026` |
| новости бумаги | `market__news_digest` по тикеру | с дедупликацией между бумагами |

Доходность портфеля считается из ответа брокера: `expectedYield` (прибыль в валюте)
делится на вложенное (стоимость минус прибыль), дневная доходность берётся из
`dailyYieldRelative`. В разборе одной бумаги эта строка не выводится — там важен
итог по бумаге, а не по портфелю.

### Секторы

Ключи секторов — как в API (`energy`, `materials`, `financial`, …), названия — русские
и без путаницы: `energy` — «нефть и газ», `utilities` — «электроэнергетика»,
`green_energy` — «зелёная энергетика», `it` — «технологии». Драйверы сектора и
чувствительность к курсу и ставке лежат в `data/company-profiles.yaml`; там же
профиль «экспортёр / внутренний рынок / импортёр» для бумаг.

Сектор берётся из справочника брокера цепочкой `invest_get_share` (uid актива) →
`invest_get_asset` (uid бренда) → `invest_get_brand` (поле `sector`). Если цепочка
не отвечает, отчёт честно пишет «сектор не определён» и показывает долю такого портфеля.

Проверка выполняется на старте: неизвестный `render`, дубль `id`, секция без
`provider` или пустой список секций — ошибка конфигурации с указанием секции.

## Что меняется без кода

- состав и порядок секций;
- заголовки секций;
- пороги концентрации и минимальной доли класса;
- набор периодов;
- текст промпта интерпретации.

## Что требует кода

- новый `provider` — новый поставщик фактов в `src/report/providers/`;
- новый тип вывода (`render`) — новый рендерер в `src/report/renderers.ts`;
- новый источник данных — адаптер в `src/sources/` (см. `docs/sources.md`).

Важно: план сбора выводится из шаблона. Убрали секцию — перестали ходить за её
данными; добавили секцию с существующим провайдером — данные начнут собираться.

## Как добавить секцию

1. Добавьте блок в `sections` шаблона с существующим `provider`.
2. Перезапустите сервис (шаблон читается при сборке отчёта).
3. Проверьте отчёт: секция появилась в указанном месте.

Тест `test/unit/report-engine.spec.ts` проверяет этот сценарий на реальном
шаблоне проекта.

## Интерпретация моделью

Секции с `interpret: true` код не заполняет: он отдаёт модели компактный
брифинг (факты без сырых JSON). Модель вызывается **отдельно на каждый раздел**
(последовательно, с повтором при сбое) и возвращает только текст раздела — без
заголовков и без префиксов вида `macro:`, поэтому парсить ответ не нужно.

Если модель недоступна или ответила пусто, отчёт остаётся: раздел сообщает
«Раздел не сформирован: модель не дала ответ», а прогон помечается частичным
(`partial: true`).

## Выгрузка отчёта

Готовый отчёт сохраняется с `reportId` и доступен по адресу:

```bash
curl -s "http://localhost:3000/api/v1/reports/<reportId>?format=md"
curl -s "http://localhost:3000/api/v1/reports/<reportId>?format=json"
curl -s "http://localhost:3000/api/v1/reports/<reportId>?format=html"
```

Формат по умолчанию — `md`. Неизвестный идентификатор и отчёт другого
пользователя отдаются как `404` с кодом `REPORT_NOT_FOUND`.

## Контракт результата

Узел возвращает `lastResult` (`kind: report | analysis | facts`, покрытие,
частичность, причина остановки). Узел ответа и журнал прогона читают это поле,
а не начало строки: отчёт опознаётся по контракту, а не по тексту.

Инструменты-агрегаторы (`portfolio__snapshot`, `market__price_dynamics`) отдают
Готовый отчёт напрямую — при условии, что ответ не помечен как отказ
(`kind: denied`) или прерванный вызов (`kind: interrupted`).
