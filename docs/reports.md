# Шаблоны отчётов

Логика отчёта живёт в файле-шаблоне, а не в коде: состав, порядок, пороги и
периоды меняются правкой YAML. Код остаётся только за поставщиков фактов
(`src/report/providers/`) и поставщиков данных (`src/sources/`).

## Где что лежит

```
reports/portfolio-review.yaml        шаблон: секции, пороги, периоды
reports/prompts/interpretation.md    промпт для секций, которые пишет модель
src/report/template.ts               схема и загрузка шаблона
src/report/engine.ts                 сборка отчёта по шаблону
src/report/providers/*.ts            поставщики фактов (имя = provider в шаблоне)
```

## Схема шаблона

```yaml
id: portfolio-review        # обязателен
version: 2                  # попадает в отчёт как templateVersion
periods: [1d, 7d, 30d, 180d]  # только эти значения
thresholds:
  concentration_high: 0.50  # доля крупнейшей позиции → «высокая»
  concentration_medium: 0.25
  min_class_share: 0.05     # порог «класс представлен»
sections:
  - id: table               # обязателен, уникален
    title: Состав портфеля
    provider: portfolio.table      # обязателен, должен быть в реестре
    render: table           # table | distribution | list | kpi | text
    params: { max: 12 }     # свободные параметры секции
    interpret: false        # true — секцию формулирует модель
```

## Область разбора

Один и тот же граф собирает три вида разбора — область определяется по вопросу:

| Вопрос | scope | Что в отчёте |
|---|---|---|
| `проанализируй мой портфель` | `portfolio` | все счета, полный набор секций |
| `разбери счёт Портфельное инвестирование` | `account` | только этот счёт: состав, структура, концентрация, налоги, пробелы |
| `разбери бумагу SBER` / `разбери Сбер` | `instrument` | только эта бумага: цена за 1/7/30/180 дней, прогноз, дивиденды, её новости, оценка сектора |

Секции с `scopes` показываются не во всех разборах: `structure`, `concentration`,
`tax`, `gaps` помечены `scopes: [portfolio, account]` — в разборе одной бумаги они
только шумят. Список областей в секции необязателен: без него секция общая.

Определение области — правило (`src/agent/scope.ts`): номер/название счёта после
слова «счёт», тикер рядом с «бумага/акции/по» или название компании из
`data/ticker-aliases.yaml`. Модель для этого не используется.

## Секции отчёта по умолчанию

| id | Что показывает | provider |
|---|---|---|
| `table` | бумага, сектор, доля, стоимость, изменение за 180 дней, мнение аналитиков | `portfolio.table` |
| `macro` | экономический цикл и рынок: ставка ЦБ, что она значит для классов активов | `macro.context` (модель) |
| `securities` | по каждой бумаге: динамика за 1/7/30/180 дней, прогноз, дивиденды, её новости | `securities.detail` |
| `opinions` | оценка каждой бумаги и её сектора | `securities.opinions` (модель) |
| `structure` | разрезы: класс, сектор, валюта, эмитент | `portfolio.structure` |
| `concentration` | крупнейшая позиция, топ-3, уровень концентрации | `portfolio.concentration` |
| `tax` | удержанные налоги и изменения налогообложения | `tax.context` |
| `gaps` | классы и секторы ниже порога | `portfolio.gaps` |
| `verdict` | диверсификация, тип стратегии, что менять | `facts.brief` (модель) |

Сектор берётся из справочника брокера цепочкой `invest_get_share` (uid актива) →
`invest_get_asset` (uid бренда) → `invest_get_brand` (поле `sector`). Если цепочка
не отвечает, отчёт честно пишет «сектор не определён» и показывает долю такого портфеля.

Проверка выполняется на старте: неизвестный `render`, дубль `id`, секция без
`provider` или пустой список секций — ошибка конфигурации с указанием секции.

## Что меняется без кода

- состав и порядок секций;
- заголовки секций;
- пороги концентрации и минимальной доли класса;
- набор периодов;
- текст промпта интерпретации.

## Что требует кода

- новый `provider` — новый поставщик фактов в `src/report/providers/`;
- новый тип вывода (`render`) — новый рендерер в `src/report/renderers.ts`;
- новый источник данных — адаптер в `src/sources/` (см. `docs/sources.md`).

Важно: план сбора выводится из шаблона. Убрали секцию — перестали ходить за её
данными; добавили секцию с существующим провайдером — данные начнут собираться.

## Как добавить секцию

1. Добавьте блок в `sections` шаблона с существующим `provider`.
2. Перезапустите сервис (шаблон читается при сборке отчёта).
3. Проверьте отчёт: секция появилась в указанном месте.

Тест `test/unit/report-engine.spec.ts` проверяет этот сценарий на реальном
шаблоне проекта.

## Интерпретация моделью

Секции с `interpret: true` код не заполняет: он отдаёт модели компактный
брифинг (факты без сырых JSON). Модель вызывается **отдельно на каждый раздел**
(последовательно, с повтором при сбое) и возвращает только текст раздела — без
заголовков и без префиксов вида `macro:`, поэтому парсить ответ не нужно.

Если модель недоступна или ответила пусто, отчёт остаётся: раздел сообщает
«Раздел не сформирован: модель не дала ответ», а прогон помечается частичным
(`partial: true`).

## Выгрузка отчёта

Готовый отчёт сохраняется с `reportId` и доступен по адресу:

```bash
curl -s "http://localhost:3000/api/v1/reports/<reportId>?format=md"
curl -s "http://localhost:3000/api/v1/reports/<reportId>?format=json"
curl -s "http://localhost:3000/api/v1/reports/<reportId>?format=html"
```

Формат по умолчанию — `md`. Неизвестный идентификатор и отчёт другого
пользователя отдаются как `404` с кодом `REPORT_NOT_FOUND`.
