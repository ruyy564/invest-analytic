# Оценка качества агента (evals)

Evals отвечают на вопрос «стало ли лучше после правки промпта, инструмента или
маршрута». Они не заменяют unit-тесты: unit проверяет функции, evals — поведение
на реальных вопросах.

## Структура

```
test/eval/cases/*.json        кейсы: вопрос, ожидаемый маршрут, инструменты, ответ
test/eval/transcripts/*.txt   записанные ответы для офлайн-режима
src/eval/*                    схема, грейдеры, агрегаты, судья
scripts/eval.mjs              раннер
scripts/eval-judge.mjs        живой судья по рубрике
```

## Формат кейса

```json
{
  "id": "buy-sber",
  "question": "Стоит ли брать Сбер?",
  "resolvedBy": "rule",
  "intent": "portfolio_review",
  "scope": "instrument",
  "target": "SBER",
  "expectedTools": ["invest_find_instrument"],
  "forbiddenTools": ["portfolio__snapshot"],
  "trials": 3,
  "tags": ["required", "instrument"],
  "answer": { "mustContain": ["## Вывод по бумаге"], "mustNotContain": ["Состав портфеля"] }
}
```

| Поле | Смысл |
|---|---|
| `expectedTools` / `forbiddenTools` | проверка выбора инструментов (tool-choice) |
| `trials` | сколько прогонов на кейс: `pass@k` (успех хотя бы раз) и `pass^k` (все прогоны) |
| `tags` | группы отчёта (`required`, `instrument`, `news`, `knowledge`, `guardrails`) |
| `transcript` | записанный ответ прямо в кейсе (иначе берётся из `transcripts/<id>.txt`) |

## Грейдеры

Код-грейдеры (всегда, без сети):

- `contains:<фрагмент>` — обязательный фрагмент есть;
- `notContains:<фрагмент>` — запрещённого фрагмента нет;
- `no-refusal` — в ответе нет отказа модели («не обладает собственным мнением»);
- `tool:<имя>` / `forbiddenTool:<имя>` — выбранные инструменты.

Грейдер по рубрике (`scripts/eval-judge.mjs`, `src/eval/judge.ts`): модель ставит
1–5 по осям, возвращает `{score, reason}`, в отчёт попадает версия рубрики.
Судью нужно калибровать на 20–30 кейсах против человека и фиксировать промпт —
иначе оценки «плывут».

## Запуск

```bash
npm run eval                        # офлайн: грейдеры на записанных ответах
npm run eval -- --mode live         # полный граф на фейковых MCP и скриптовой модели
npm run eval -- --mode judge        # живой судья (нужен LLM_API_KEY)
npm run eval -- --cases test/eval/cases/dialogues.json --transcripts test/eval/transcripts
```

Офлайн-режим завершается с ненулевым кодом, если есть проваленные кейсы.
Кейсы без записанного ответа перечисляются как пропущенные и не считаются
провалом.

## Как добавить кейс

1. Скопируйте `test/eval/cases/regression-template.json` в нужную группу.
2. Заполните `id`, `question`, ожидаемый маршрут, `tags`.
3. Добавьте `answer.mustContain` / `mustNotContain` — по одному требованию на строку.
4. Положите записанный ответ в `test/eval/transcripts/<id>.txt`.
5. Прогоните `npm run eval` и убедитесь, что кейс проходит (или падает ожидаемо).

## Правило регрессии

Каждый подтверждённый сбой поведения, найденный в эксплуатации, становится
кейсом с тегом `required`. Правка не считается готовой, пока этот кейс не
проходит, а остальные обязательные кейсы не остались зелёными.

## Ограничения

- Офлайн-режим проверяет только записанные ответы: он ловит регрессии текста и
  грейдеров, но не изменение поведения модели.
- Живой режим требует ключей провайдера и стоит денег: запускается вручную или
  по расписанию, не в каждом коммите.
- Автоматического «перезаписать транскрипты» пока нет: обновление выполняется
  осознанно после проверки ответа.
