# База знаний по инвестициям

Агент объясняет, **как трактовать** собранные данные, и отвечает на вопросы о понятиях.
Знания живут отдельным файлом данных — их состав и формулировки меняются без правки кода.

```
промпт раздела отчёта      ← отбор по разделу и секторам портфеля
системный промпт агента    ← чек-лист принятия решений
справочный ответ (ветка)   ← тема по вопросу пользователя
```

## Что внутри

`data/investment-knowledge.yaml`, темы:

| id | О чём |
|---|---|
| `cycles` | экономические циклы: фазы, что обычно сильнее в каждой фазе |
| `macro` | ключевая ставка, инфляция, курс и их связь с оценками бумаг |
| `multiples` | P/E, P/B, EV/EBITDA, дивидендная доходность, ROE, долг/EBITDA |
| `diversification` | классы, секторы, валюты, корреляция, ребалансировка |
| `psychology` | искажения решений: неприятие потерь, FOMO, якорение, дисциплина |
| `sector-dependencies` | от чего зависит каждый сектор портфеля |
| `commodities` | как цены на металлы влияют на эмитентов и издержки |
| `history` | кризисы 1998, 2008, 2014, 2020, 2022 и восстановление |
| `decision-checklist` | последовательность проверок перед решением |
| `sources` | литература и аналитика БКС как ориентиры |

## Формат темы

```yaml
  - id: multiples
    title: Мультипликаторы
    summary: Определение в одно-два предложения — его цитирует справочный ответ.
    points:
      - Тезис одной строкой
    sections: [opinions, verdict]   # разделы отчёта, где тема полезна
    sectors: [финансы]              # секторы портфеля в названиях брокера
    keywords: [мультипликатор, p/e] # термины вопроса
    sources:
      - Асват Дамодаран, «Инвестиционная оценка»
```

Правила файла:

- YAML-подмножество, которое разбирает `src/report/yaml.ts`: каждый тезис — одна строка,
  без переносов и без двоеточия с пробелом внутри тезиса;
- числа в тезисах — исторические иллюстрации, а не текущие значения рынка;
- `id` уникален: по нему тема запрашивается принудительно (`required`).

## Отбор контекста

`selectKnowledge` считает вес темы:

| Признак | Вес |
|---|---|
| раздел отчёта (позиция в `sections`) | 4 / 3 / 2 |
| сектор портфеля в `sectors` | +2 для раздела по бумагам, +1 для остальных |
| термин вопроса в `keywords` | +1 |

Порядок при равном весе — как в файле. По умолчанию берётся не больше трёх тем
(`DEFAULT_KNOWLEDGE_LIMIT`), для разделов `macro` и `verdict` принудительно добавляется
`decision-checklist`. В блок попадает не больше пяти тезисов темы, общий объём ограничен
`KNOWLEDGE_MAX_CHARS` (по умолчанию 1800 символов) и режется по целым строкам.

Секторы берутся из структуры портфеля; в разборе бумаги — из её карточки.

## Граница «знания ≠ данные»

В начало блока добавляется преамбула: числа, ставки, цены и даты берутся только из
брифинга, а выводы на основе принципов помечаются «(оценка)». То же правило продублировано
в `reports/prompts/interpretation.md` и в промпте агента.

## Справочные ответы

Вопрос вида «что такое P/E» попадает в ветку `knowledge`:

- правило проверяется до обращения к модели и до эвристики «разбор портфеля»;
- ответ собирается кодом: заголовок, определение, до шести тезисов, источник и напоминание,
  что это не индивидуальная инвестиционная рекомендация;
- если темы нет — ответ перечисляет доступные темы вместо выдуманного определения;
- данные брокера не читаются, подтверждение не запрашивается, `report` не создаётся.

## Конфигурация

```dotenv
KNOWLEDGE_ENABLED=true
KNOWLEDGE_FILE=data/investment-knowledge.yaml
KNOWLEDGE_MAX_CHARS=1800
```

- `KNOWLEDGE_ENABLED=false` — откат: блок знаний не добавляется, справочная ветка выключена,
  вопрос о понятии уходит прежним маршрутом, а справка о возможностях не обещает объяснений.
- Файла нет или формат неверный — сервис работает как раньше, причина пишется в лог
  (`[knowledge] база знаний недоступна ...`).

## Как расширить

1. Добавьте тему в `data/investment-knowledge.yaml` (заголовок, определение, тезисы, теги).
2. Проверьте `npm test -- knowledge` — тест читает реальный файл и проверяет обязательные темы.
3. Если тема должна попадать в конкретный раздел, укажите его первым в `sections`.

## Тесты

- `test/unit/knowledge.spec.ts` — загрузка, деградация, отбор, лимиты, формат ответа;
- `test/unit/knowledge-intent.spec.ts` — правило справочного вопроса и область ассистента;
- `test/unit/report-engine.spec.ts` — блок знаний в интерпретации разбора;
- `test/e2e/agent-graph.e2e-spec.ts` — справочный ответ без данных и подтверждения.
