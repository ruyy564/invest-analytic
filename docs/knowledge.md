# База знаний по инвестициям

Агент объясняет, **как трактовать** собранные данные, и отвечает на вопросы о понятиях.
Знания — это каталог файлов-тем, по файлу на тему: состав и формулировки меняются без
правки кода, а большой файл не нужен.

```
промпт раздела отчёта      ← отбор по разделу и секторам портфеля
системный промпт агента    ← чек-лист принятия решений
справочный ответ (ветка)   ← тема по вопросу пользователя, с подразделами
```

## Структура

```
data/knowledge/
  01-cycles.yaml            циклы: фазы, индикаторы, классы активов
  02-macro.yaml             ставка, инфляция, курс
  03-multiples.yaml         P/E, P/B, EV/EBITDA, ROE, долг
  04-diversification.yaml   оси диверсификации, корреляция, ребалансировка
  05-psychology.yaml        искажения, эмоциональный цикл, дисциплина
  06-sectors.yaml           зависимость каждого сектора
  07-commodities.yaml       металлы и влияние на эмитентов
  08-history.yaml           кризисы 1998–2022, истории компаний
  09-checklist.yaml         проверки перед покупкой, продажей, пересмотром
  10-sources.yaml           БКС, книги, как читать источники
  11-reporting.yaml         как читать отчётность: P&L, денежный поток, долг, качество прибыли
  12-taxes.yaml             налоги и комиссии: НДФЛ, дивиденды, купоны, льготы, ИИС
  13-crises.yaml            кризисы и поведение эмитентов, что проверять заранее
  14-bankruptcies.yaml      банкротства и санации: причины, признаки, что с бумагами
  15-strategies.yaml        стратегии на акциях и облигациях, правила риска
  16-instruments.yaml       инструменты: акции, облигации, фонды, срочный рынок, как платить
  17-trade-balance.yaml     экспортёры, импортёры, внутренний рынок: что влияет
```

Порядок чтения задаёт имя файла, поэтому префикс `NN-` — часть имени. Один файл может
содержать несколько тем: каталог читается целиком, темы склеиваются в одну базу.

Каждая тема: `title`, `summary` (определение — его цитирует ответ), `points` (ключевые
тезисы), `details` (подразделы с тезисами), `pitfalls` (частые ошибки), теги
`sections` / `sectors` / `keywords` и `sources`.

## Формат файла

```yaml
version: 1
topics:
  - id: multiples
    title: Мультипликаторы
    summary: Определение в одно-два предложения — его цитирует справочный ответ.
    points:
      - Тезис одной строкой
    details:
      - title: Ценовые мультипликаторы
        points:
          - P/E — цена к прибыли; для циклических компаний прибыль нормализуют
    pitfalls:
      - Сравнивать P/E компаний из разных отраслей
    sections: [opinions, verdict]   # разделы отчёта, где тема полезна
    sectors: [финансы]              # секторы портфеля в названиях брокера
    keywords: [мультипликатор, p/e] # термины вопроса
    sources:
      - Асват Дамодаран, «Инвестиционная оценка»
```

Правила формата:

- разбирается YAML-подмножество из `src/report/yaml.ts`: каждый тезис — одна строка,
  без переносов; многострочные блоки не поддерживаются;
- ключи — латинские (`id`, `title`, `points`), поэтому русский текст с двоеточием
  («Урок: …») остаётся строкой, а не превращается в объект;
- `id` уникален: при совпадении первый файл по порядку выигрывает, дубликат пишется в лог;
- числа в тезисах — исторические иллюстрации, а не текущие значения рынка.

## Что делать при добавлении темы

1. Создайте файл `data/knowledge/NN-<id>.yaml` со следующего по порядку номером.
2. Заполните `title`, `summary`, `points`, при необходимости `details` и `pitfalls`,
   поставьте теги и источники.
3. Проверьте `npm test -- knowledge`: тест читает реальный каталог и проверяет каждую тему.

Ошибиться в формате не страшно: битый файл пропускается с предупреждением
`[knowledge] файл темы пропущен`, остальные темы продолжают работать.

## Отбор контекста

`selectKnowledge` считает вес темы:

| Признак | Вес |
|---|---|
| раздел отчёта (позиция в `sections`) | 4 / 3 / 2 |
| сектор портфеля в `sectors` | +2 для раздела по бумагам, +1 для остальных |
| термин вопроса в `keywords` | +1 |

Темы, закреплённые за секцией в шаблоне (`knowledge: [strategies]` у `verdict`,
`knowledge: [reporting]` у `securities`, `knowledge: [taxes]` у `tax`), идут первыми
вне зависимости от веса — так стратегия и налоги гарантированно попадают в промпт.

Порядок при равном весе — как в каталоге. По умолчанию берётся не больше трёх тем
(`DEFAULT_KNOWLEDGE_LIMIT`); для разделов `macro` и `verdict` принудительно добавляется
`decision-checklist`. В промпт попадают заголовок, определение и не больше пяти тезисов
темы: подразделы и ошибки в промпт не идут, чтобы не вытеснять факты брифинга.

Секторы берутся из структуры портфеля; в разборе бумаги — из её карточки.

## Справочный блок в отчёте

База знаний участвует в отчёте дважды:

1. **В промптах интерпретируемых разделов** — `macro`, `opinions`, `verdict` получают
   подобранный блок принципов (`promptBlock`), чтобы модель трактовала факты, а не
   выдумывала числа.
2. **Отдельной секцией «Справочный контекст»** — секция `knowledge` (провайдер
   `knowledge.context`) показывает темы, отобранные под секторы портфеля или под
   конкретную бумагу: заголовок, определение и до трёх тезисов на тему. Секция помечена
   `optional: true`: если база знаний выключена или файлов нет, секция просто исчезает —
   без «Данных нет» и без пометки отчёта частичным.

Правила отбора для секции:

| Разбор | Раздел отбора | Обязательные темы |
|---|---|---|
| портфель и счёт | `verdict` | — (по весу: диверсификация, психология, чек-лист) |
| бумага | `securities` | `reporting` и `multiples` — отчётность и мультипликаторы |

Фундаментальные значения (P/E, P/B, EV/EBITDA) брокер через MCP не отдаёт:
`invest_get_asset_fundamentals` возвращает пустой список. Поэтому в карточке — цена,
динамика, прогноз аналитиков, дивиденды и сделки инсайдеров, а мультипликаторы
объясняет справочный блок: считать их нужно по отчётности эмитента, а не по выдуманным
числам.

Блок всегда заканчивается пометкой «принципы трактовки, а не данные рынка»: числа
остаются за фактами из брифинга.

## Граница «знания ≠ данные»

В начало блока добавляется преамбула: числа, ставки, цены и даты берутся только из
брифинга, а выводы на основе принципов помечаются «(оценка)». Правило продублировано
в `reports/prompts/interpretation.md` и в промпте агента.

## Справочные ответы

Вопрос вида «что такое P/E» попадает в ветку `knowledge`:

- правило проверяется до обращения к модели и до эвристики «разбор портфеля»;
- ответ собирается кодом: заголовок, определение, до восьми тезисов, все подразделы,
  частые ошибки, источники и напоминание, что это не инвестиционная рекомендация;
- если темы нет — ответ перечисляет доступные темы вместо выдуманного определения;
- данные брокера не читаются, подтверждение не запрашивается, `report` не создаётся.

## Конфигурация

```dotenv
KNOWLEDGE_ENABLED=true
KNOWLEDGE_DIR=data/knowledge
# KNOWLEDGE_FILE=data/my-notes.yaml
KNOWLEDGE_MAX_CHARS=1800
```

- `KNOWLEDGE_DIR` — каталог тем; `KNOWLEDGE_FILE` — необязательный дополнительный файл
  (например, личные заметки), читается после каталога.
- `KNOWLEDGE_ENABLED=false` — откат: блок знаний не добавляется, справочная ветка выключена,
  вопрос о понятии уходит прежним маршрутом, справка о возможностях не обещает объяснений.
- Каталога нет или все файлы битые — сервис работает как раньше; недоступная тема
  перечисляется в логе и не мешает остальным.

## Тесты

- `test/unit/report-engine.spec.ts` — блок знаний в интерпретации разбора;
- `test/e2e/agent-graph.e2e-spec.ts` — справочный ответ без данных и подтверждения.
